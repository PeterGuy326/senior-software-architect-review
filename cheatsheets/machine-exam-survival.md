# 机考操作 · 过线保命卡

> 本卡只解决“会做但因机考操作丢分”的风险。考试界面可能调整，**以当期官方模拟系统和准考证说明为准**；不要把第三方模拟器的按钮位置当成固定规则。

## 一、考前至少完成 2 次全流程演练

- 一次按真实时长完成综合或案例；
- 一次完整输入不少于 2500 字论文；
- 至少练一次网络图、架构图或表格型答案；
- 验证中文输入法、数字/英文符号、复制粘贴和滚动定位习惯；
- 演练“误删一段、撤销、重新排版、检查遗漏”的恢复动作。

只看操作视频不算完成演练，必须实际输入并提交一份完整答案。

## 二、开考前检查

1. 核对科目、题号和作答区域；
2. 测试中文、英文、数字和常用标点输入；
3. 确认剩余时间、题目导航和已答状态的显示位置；
4. 不自行改变系统设置，不打开无关程序；
5. 发现设备、键盘、鼠标或界面异常，立即举手报告并记录发生时间。

## 三、综合知识

- 先做确定题，疑难题标记后返回；
- 计算题先在草稿区写公式和中间量，再录入答案；
- 最后检查未作答、错位和误选；
- 不因题号跳转而改变原定节奏。

## 四、案例分析

### 选题与时间

- 先通读所有题，确认必做题和两个选做题；
- 每题按固定时间盒推进，卡住的小问先留标记；
- 先写结论，再写理由、技术名词和量化指标。

### 输入格式

- 每个小问单独分段，使用“问题 1 / 问题 2”或清晰序号；
- 填表题按题目顺序逐项写，不改变字段含义；
- 对比题优先使用短表格或分点，不写大段散文；
- 画图题确保节点名、关系、方向和图例可读。

### 画图最低要求

- 网络图：节点/活动、工期、依赖方向清楚；
- 架构图：边界、构件、连接件、协议或数据流清楚；
- UML：关系类型和多重度按题目要求标注；
- 图画不完时，先用文字列出关键节点和关系，避免整问空白。

## 五、论文写作

### 输入顺序

1. 先写题目要求对应的摘要骨架；
2. 列 4–6 个正文标题；
3. 先完成项目背景和核心实践，再回填摘要；
4. 最后补量化效果、问题反思和结尾。

### 防丢分检查

- 明确本人角色、项目规模、周期和约束；
- 理论部分必须回答题目指定问题；
- 实践部分写“为什么选、怎么做、遇到什么问题、如何验证”；
- 至少给出 3 个可信指标；
- 不把范文中的公司、客户和数字原样照搬；
- 完整作文不少于 2500 字，摘要和提纲不能替代正文。

### 输入风险

- 每完成一节就快速检查是否落在正确位置；
- 大段调整前先确认选区，避免覆盖相邻内容；
- 不在最后十分钟进行大规模重排；
- 若系统提供预览，至少在交卷前查看一次整体结构。

## 六、异常处理

- 界面卡顿：停止重复点击，记录题号和时间，立即举手；
- 输入丢失：先尝试系统允许的撤销/恢复，再联系监考；
- 设备更换或中断：确认剩余时间和答案是否保留；
- 不擅自刷新、退出或重启；
- 以监考指令和考场记录为准。

## 七、最后检查清单

### 综合

- [ ] 所有题都有答案
- [ ] 标记题已复查
- [ ] 计算题单位和符号无误

### 案例

- [ ] 必做题 + 两道选做题正确
- [ ] 每个小问都有结论或关键词
- [ ] 图表标签和方向完整
- [ ] 没有把备选题答案写到错误题号

### 论文

- [ ] 题目要求全部回应
- [ ] 项目真实且前后一致
- [ ] 理论、实践、效果、反思齐全
- [ ] 字数、段落和摘要完整

## 八、练习记录

每次演练只记录四项：完成时间、操作失误、损失分钟数、下次纠正动作。操作问题不能计入知识掌握，但必须在考前消除。
