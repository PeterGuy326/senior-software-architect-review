## 一、考场策略（必读）

- **75 题按板块优先级答题**：§4 → §6 → §1 → §7 先做（合计 63.1%，稳态 47 题/年）
- **时间预算**：150 分钟 / 75 题 ≈ 2 分钟/题；单题超 3 分钟立刻蒙
- **得分公式**：4 大板块打 80% + 其他板块蒙 40% = 46 分（刚好过线）
- **兜底蒙题原则**（无思路时）：
  - 3 长 1 短 → 选**短**（干扰项常故意加长）
  - 4 选 2 犹豫 → 选**中间偏后**（B/C）
  - 出现"必须""完全""所有""绝对""唯一"字眼 → 大概率是**干扰项**
  - 2 个选项字面相近 → 90% 答案在这两个里
  - 完全不会 → 全部涂 **B 或 C**（历年答案分布 B/C 略高于 A/D）
- **必做题号习惯**：题号 Q23-Q45 集中在 §4 §6，Q71-Q75 固定英语，Q60-Q68 常考知产/质量属性
- **上午 15 分钟前必须涂完卡**：宁可蒙也不留空

## 二、🔥🔥🔥 §4 软件工程（21.8% ≈ 14 题/年，必背 60 条）

### §4.1 软件过程模型（每年 2-3 题）

- **瀑布**：文档驱动、阶段冻结不回退、只适合需求明确
- **原型**：快速验证需求、抛弃型/演化型、需求模糊时用
- **增量**：分批交付可运行版本、风险低、早期见收益
- **螺旋**：4 象限（计划/风险/开发/评估），🔥**风险驱动**、大型项目
- **RAD**：快速应用开发、时间盒、组件化
- **RUP**：4 阶段（初启/精化/构建/移交）+ 9 工作流，🔥**以架构为中心、迭代、用例驱动**
- **敏捷/Scrum**：Sprint 2-4 周、拥抱变化、PO+SM+Team、每日站会
- **XP**：结对编程、TDD、持续集成、简单设计
- **喷泉模型**：面向对象、迭代无间隙
- **形式化方法**：数学证明、高安全领域
- **V 模型**：测试与开发对应（单元-详细/集成-概要/系统-需求/验收-用户）
- **W 模型**：V 改进版，测试贯穿全生命周期

### §4.2 需求工程（每年 1-2 题）

- **五大活动**：需求获取 → 分析 → 规格说明 → 验证 → 管理
- **获取方法**：面谈、专题讨论、问卷、观察、原型、头脑风暴、联合应用开发（JAD）
- **需求分类**：业务需求、用户需求、功能需求、非功能需求（质量属性）
- **需求规格说明**：SRS 文档、写清"做什么"不写"怎么做"
- **CCB 变更控制委员会**：审批一切需求变更，🔥必考
- **需求跟踪矩阵**：正向（需求→设计→代码→测试）+ 反向双向可追溯
- **需求基线**：通过评审的需求集合，变更必须走 CCB
- **需求验证方法**：评审、原型、测试用例先行

### §4.3 结构化分析 SASD（每年 1 题）

- **图示工具**：DFD、ERD、STD 状态转换图、流程图、NS、PAD、PDL、判定表/树
- **DFD 4 要素**：加工（圆）、数据流（箭头）、数据存储（双线）、外部实体（方框）
- **DFD 分层**：顶层图（1 个加工）→ 0 层图 → 子图，父子图**数据流守恒**
- **数据字典 4 类条目**：数据项、数据结构、数据流、加工（不含外部实体）
- **MDA 模型驱动**：CIM → PIM → PSM → 代码
- **结构化设计原则**：自顶向下、逐步求精、模块化

### §4.4 概要设计与 UML 视图（每年 2 题）

- **模块化**：高内聚低耦合、每个模块单一职责
- **信息隐蔽**：Parnas 原则，模块内部实现对外不可见
- **抽象/逐步求精/结构化**：三大基本原则
- **UML 五视图（4+1 视图）**：
  - **逻辑视图**：类图、对象图（面向最终用户，关注功能）
  - **开发视图**：包图、构件图（面向程序员，关注管理）
  - **进程视图**：活动图、序列图（面向系统集成人员，关注性能并发）
  - **物理视图**：部署图（面向系统工程师，关注拓扑）
  - **场景/用例视图**：用例图（贯穿其余四个，验证架构）
- **SysML**：系统建模语言，UML 扩展、适合工程系统
- **顺序图 vs 通信图**：都表示对象交互，顺序图强调时间、通信图强调结构

### §4.5 软件设计与 UML 建模（每年 2-3 题，🔥最高频）

- **内聚强度（强→弱）**：功能 > 顺序 > 通信 > 过程 > 时间 > 逻辑 > 偶然
- **耦合强度（弱→强）**：非直接 < 数据 < 标记 < 控制 < 外部 < 公共 < 内容
- 🔥**背口诀**：内聚要强、耦合要弱
- **UML 图 14 种**（结构 7 + 行为 7）：
  - 结构图：类、对象、构件、部署、包、组合结构、制品
  - 行为图：用例、活动、状态、序列、通信、时序、交互概览
- **UML 4 种关系**：
  - **依赖**（虚线箭头）：临时使用
  - **关联**（实线）：长期结构关系，含**聚合**（空心菱形，弱）、**组合**（实心菱形，强，同生共死）
  - **泛化**（实线空心三角）：继承
  - **实现**（虚线空心三角）：接口实现
- 🔥**类关系耦合强度**：继承 > 组合 > 聚合 > 关联 > 依赖
- **面向对象基本概念**：对象、类、封装、继承、多态、消息、接口、重载、覆盖

### §4.6 项目管理与配置管理（每年 1 题）

- **PMBOK 十大知识域**：整合、范围、进度、成本、质量、资源、沟通、风险、采购、干系人
- **配置管理**：版本控制、变更控制、基线管理、状态审计
- **SCI 软件配置项**：需求/设计/代码/测试/手册
- **进度管理**：Gantt（时间轴）、PERT（网络图，含关键路径）
- **风险应对**：规避 / 转移 / 减轻 / 接受

### §4.7 软件测试与 CMMI（每年 2-3 题，🔥高频）

- **黑盒方法**：等价类、边界值、判定表、因果图、正交实验、错误推测
- **白盒方法**：语句覆盖 < 判定覆盖 < 条件覆盖 < 判定/条件覆盖 < 条件组合覆盖 < 路径覆盖
- **测试阶段**：单元 → 集成 → 系统 → 验收 → 回归
- **集成策略**：自顶向下（需桩）、自底向上（需驱动）、大爆炸、三明治
- **α 测试 vs β 测试**：α 用户在开发方现场；β 用户在自己环境
- **回归测试**：修改后重跑，防止引入新缺陷
- 🔥**CMMI 5 级**：初始（1）→ 已管理（2）→ 已定义（3）→ 量化管理（4）→ 优化（5）
- **CMMI 表示法**：阶段式（5 级）、连续式（能力等级 0-5）
- **McCabe 圈复杂度**：V(G) = 边数 − 节点数 + 2，或判定节点数 + 1

### §4.8 逆向工程

- **4 级抽象**：实现级 → 结构级 → 功能级 → 领域级（越高越抽象）
- **再工程**：逆向工程 + 重构

## 三、🔥🔥🔥 §6 系统架构（17.6% ≈ 11 题/年，必背 45 条）

### §6.1 架构基本概念（每年 1 题）

- **IEEE 1471-2000**：架构 = 组件 + 连接件 + 约束 + 决策原理
- **架构 = 关键决策集合**（Bass 定义）
- **架构 4 要素**：构件、连接件、配置、约束
- **架构生命周期 6 阶段**：需求 → 设计 → 文档化 → 复审 → 实现 → 演化

### §6.2 构件与 4+1 视图（每年 1-2 题）

- **Kruchten 4+1 视图**：逻辑 + 开发 + 进程 + 物理 + 场景
- **构件三特性**：独立部署、组装、无持久状态
- **EJB 三种 Bean**：会话 Bean（Session）、实体 Bean（Entity）、消息驱动 Bean（MDB）
- **CORBA**：OMG 制定，跨语言分布式对象，核心 ORB
- **J2EE**：Web 层（Servlet/JSP）+ 业务层（EJB）+ 数据层
- **中间件类型**：数据库中间件、消息中间件、事务中间件、对象中间件

### §6.3 架构风格 / ABSD（每年 2 题，🔥最高频）

- **五大架构风格族**：
  - **数据流**：批处理、管道-过滤器（Unix、编译器）
  - **调用/返回**：主程序-子程序、OO、层次结构（TCP/IP）
  - **独立构件**：进程通信、事件驱动/隐式调用
  - **虚拟机**：解释器、规则系统（专家系统、Prolog）
  - **仓库**：数据库、黑板、超文本（黑板 = AI 领域，共享数据 + 知识源 + 控制）
- **ABSD 基于架构的软件设计**：
  - **驱动**：质量 + 商业需求 + 功能需求
  - **迭代过程**：视图 + 用例 + 质量场景驱动
  - **6 阶段**：架构需求 → 设计 → 文档化 → 复审 → 实现 → 演化
- **DSSA 特定领域软件架构**：3 层次（领域开发环境/领域特定应用开发环境/应用执行环境）
- **DSSA 3 阶段**：领域分析 → 领域设计 → 领域实现

### §6.4 分层架构 / SOA / C-S（每年 1-2 题）

- **C/S 两层**：胖客户端、服务器压力小、维护难
- **三层 C/S**：表现层 + 业务逻辑层 + 数据层
- **B/S**：浏览器-服务器，跨平台、维护易、交互弱
- **MVC**：模型 + 视图 + 控制器，视图订阅模型（观察者模式）
- **SOA 服务导向**：粗粒度、松耦合、标准协议（SOAP/REST）、可复用
- **SOA 关键协议**：SOAP、WSDL、UDDI、BPEL（编排）
- **ESB 企业服务总线**：SOA 核心，消息路由/转换/协议桥接
- **微服务**：细粒度、独立部署、去中心化治理、轻量通信（REST）
- **微服务 vs SOA**：微服务更小、更独立、每服务一库

### §6.5 设计模式（每年 1-2 题）

- **GoF 23 模式三大类**：
  - **创建型 5**：单例、工厂方法、抽象工厂、建造者、原型
  - **结构型 7**：适配器、桥接、组合、装饰、外观、享元、代理
  - **行为型 11**：责任链、命令、解释器、迭代器、中介者、备忘录、观察者、状态、策略、模板方法、访问者
- **常考搭配速记**：
  - **桥接**：分离抽象和实现（形状 × 颜色）
  - **适配器**：接口转换；**装饰器**：动态加职责；**代理**：控制访问
  - **观察者**：一对多依赖，发布-订阅；**策略**：算法族可替换
  - **命令**：请求封装成对象；**模板方法**：骨架 + 钩子

### §6.6 中间件与新技术（每年 1 题）

- **DDD**：限界上下文、聚合根、实体、值对象、领域事件
- **微服务断路器**：Hystrix、Sentinel（熔断/降级/限流）
- **API 网关**：认证、限流、路由、聚合
- **服务注册发现**：Eureka、Consul、Nacos

### §6.7 复用与产品线

- **复用级别**：代码 < 设计 < 分析 < 领域
- **软件产品线**：核心资产 + 产品开发，架构级复用

## 四、🔥🔥🔥 §1 计算机系统（13.7% ≈ 8 题/年，必背 35 条）

### §1.2 计算机组成（每年 1 题）

- **冯·诺依曼 5 部件**：运算器、控制器、存储器、输入、输出
- **哈佛结构**：指令与数据分开存储（DSP 常用）
- **冯诺依曼**：指令与数据同一存储器
- **CISC vs RISC**：复杂/简单指令、微程序/硬布线
- **CPU vs GPU vs DSP vs FPGA**：通用/图形并行/信号处理/可编程门阵列
- **流水线**：吞吐率 = 1/max(各段时间)

### §1.3 存储管理 / OS 内核（每年 2 题，🔥最高频）

- **进程状态 5 态**：新建、就绪、运行、阻塞、终止
- **PCB 进程控制块**：进程唯一标识
- **进程 vs 线程**：进程有独立资源，线程共享进程资源、切换轻
- **信号量 P/V**：P 申请（−1，<0 阻塞）、V 释放（+1，≤0 唤醒）
- **死锁 4 必要条件**：互斥、请求保持、不剥夺、循环等待
- **死锁处理**：预防、避免（银行家算法）、检测、解除
- **银行家算法**：分配前预判是否安全序列
- **页式管理**：逻辑地址 = 页号 + 页内偏移，通过页表 → 物理地址
- **段式管理**：逻辑地址 = 段号 + 段内偏移，段长可变
- **段页式**：先分段再分页
- **页面置换算法**：OPT（最优）、FIFO、LRU、LFU、Clock
- **抖动**：置换频繁，工作集不足
- **虚拟存储**：局部性原理（时间 + 空间）

### §1.4 OS 调度与文件系统（每年 1 题）

- **进程调度**：先来先服务 FCFS、短作业优先 SJF、优先级、时间片轮转、多级反馈队列
- **磁盘调度**：FCFS、SSTF（最短寻道）、SCAN（电梯）、C-SCAN、LOOK
- **文件目录**：单级、两级、树形、无环图
- **文件物理结构**：连续、链接、索引（一级/多级/混合）
- **多级索引容量**：直接块 + 一级 + 二级 + 三级，🔥算容量必考
- **位示图**：1 位表示 1 块空闲/占用，位号 → 块号换算

### §1.5 网络协议与嵌入式（每年 1-2 题）

- **实时系统**：硬实时（错过=灾难）、软实时（错过=降级）
- **RMS 单调速率调度**：周期越短优先级越高
- **EDF 最早截止期优先**：动态优先级
- **SoC 片上系统**：CPU + 存储 + 外设集成单芯片
- **嵌入式操作系统**：VxWorks、μC/OS、RT-Linux、FreeRTOS

### §1.6 计算机网络（每年 2 题，🔥高频）

- **OSI 7 层**：物理、数据链路、网络、传输、会话、表示、应用
- **TCP/IP 4 层**：网络接口、网际、传输、应用
- **TCP vs UDP**：可靠有连接/不可靠无连接、字节流/报文、慢/快
- **常见端口**：FTP 20/21、SSH 22、Telnet 23、SMTP 25、DNS 53、HTTP 80、POP3 110、HTTPS 443
- **DHCP**：DISCOVER → OFFER → REQUEST → ACK，🔥四报文
- **DNS**：正向解析（域名→IP）、反向解析（IP→域名，PTR 记录）
- **子网掩码 / CIDR**：/24 = 255.255.255.0，主机数 = 2^n − 2
- **CRC 循环冗余校验**：模 2 除法，用于数据链路层差错检测
- **路由协议**：RIP（距离矢量，跳数≤15）、OSPF（链路状态）、BGP（外部）
- **IPv6**：128 位，地址空间大、无 NAT、内置 IPsec

## 五、🔥🔥🔥 §7 质量属性（10% ≈ 6 题/年，必背 25 条）

### §7.1 六大质量属性 + 战术（每年 2-3 题）

- **可用性**：故障检测（心跳、Ping/Echo）、故障恢复（冗余、回滚、事务、重试）、故障预防（进程监视器、进程复活）
- **性能**：资源需求（减少计算开销）、资源管理（并发、并行、增加资源）、资源仲裁（调度策略、优先级、负载均衡）
- **安全性**：抵抗攻击（认证、授权、加密、限制暴露、防火墙）、检测攻击（入侵检测）、恢复攻击（审计追踪、恢复可用性）
- **可修改性**：局部化修改（内聚）、防止连锁反应（信息隐藏、接口分离）、延迟绑定（配置文件、多态）
- **可测试性**：输入/输出记录/回放、内置监测器、接口-实现分离
- **易用性**：运行时用户支持（撤销/取消）、界面一致性、用户模型

### §7.2 质量属性场景 6 元组（每年 2 题，🔥必背）

- **6 要素**：
  1. **刺激源** Source：谁发起（用户/内部/外部系统）
  2. **刺激** Stimulus：什么事件（请求/故障/攻击/变更）
  3. **制品** Artifact：影响谁（系统/数据/进程）
  4. **环境** Environment：什么状态（正常/降级/超载）
  5. **响应** Response：系统怎么做（处理/记录/通知）
  6. **响应度量** Measure：可量化（<1s、99.9%）
- 🔥**背套路**：谁 + 干了什么 + 对谁 + 什么状态 + 系统响应 + 量化指标

### §7.3 ATAM 评估方法（每年 1-2 题）

- **ATAM 4 类点**（🔥必背）：
  - **敏感点**：一个决策影响多个质量属性
  - **权衡点**：一个决策**正面影响一个、负面影响另一个**质量属性
  - **风险点**：架构决策可能带来问题
  - **非风险点**：架构决策是安全的
- **ATAM 9 步骤**（大致记住）：展示 ATAM → 展示商业动机 → 展示架构 → 识别架构方法 → 生成质量属性效用树 → 分析架构方法 → 头脑风暴场景 → 分析架构方法 → 展示结果
- **评估方法对比**：
  - **SAAM**：早期方法、场景驱动、单质量属性（可修改性）
  - **ATAM**：多质量属性权衡分析，🔥最常考
  - **CBAM**：成本效益分析，ATAM 之后使用
- **效用树**：根 → 质量属性 → 属性细化 → 场景（含 <重要性, 难度> 二元组）

## 六、🔥🔥 §5 §13 §3 §11 §10（挑背 45 条）

### §5 数据库（5.6% ≈ 4 题/年）

- **三级模式**：外模式（视图）/ 概念（表） / 内（存储），2 级映射保独立性
- **三类完整性**：实体（主键非空唯一）、参照（外键必须存在或 NULL）、用户定义
- **范式**：
  - **1NF**：字段不可再分
  - **2NF**：消除部分依赖（非主属性完全依赖主键）
  - **3NF**：消除传递依赖
  - **BCNF**：主属性也不部分/传递依赖
  - **4NF**：消除多值依赖
- **关系代数 5 基本**：并 ∪、差 −、笛卡尔积 ×、投影 π、选择 σ；导出：交、连接、除
- **事务 ACID**：原子、一致、隔离、持久
- **并发问题**：脏读、不可重复读、幻读、丢失更新
- **隔离级别**：读未提交 < 读已提交 < 可重复读 < 串行化
- **NoSQL 4 类**：键值 Redis、列式 HBase、文档 MongoDB、图 Neo4j
- **CAP**：一致性/可用性/分区容忍，三选二

### §13 专业英语（5.3% ≈ 5 题/年，Q71-75 固定位置）

- 🔥**答题技巧**：Q71-75 同一段材料，5 题连环，先通读圈关键词
- **高频名词**：architecture、component、interface、pattern、layer/tier、middleware、framework、instance、deployment、integration
- **高频形容词**：reusable、scalable、maintainable、available、reliable、secure、loosely-coupled、highly-cohesive
- **OO 术语**：encapsulation、inheritance、polymorphism、abstraction、cohesion、coupling
- **架构术语**：microservice、SOA、containerization、orchestration、pipeline、message queue、load balancer
- **蒙题保底**：读不懂全部选 **A 或 B**

### §3 信息安全（4.6% ≈ 3 题/年）

- 🔥**CIA 三要素**：机密性 Confidentiality、完整性 Integrity、可用性 Availability
- **扩展**：真实性、不可否认性、可控性
- **对称加密**：DES 56、3DES 168、**AES 128/192/256**、IDEA 128、RC4、**SM4**（国密）
- **非对称**：**RSA**（大素数）、ECC（椭圆曲线）、DSA、DH（密钥交换）、**SM2**（国密）
- **Hash**：MD5 128、SHA-1 160、SHA-256、**SM3** 256（国密）
- **数字签名**：发送方**私钥签** → 接收方**公钥验**（保不可否认）
- **数字信封**：对称密钥用接收方**公钥**加密（保机密性）
- **PKI**：CA 颁发、RA 注册、CRL 吊销、X.509 证书
- **安全 5 等级**（GB 17859）：用户自主→系统审计→安全标记→结构化保护→访问验证
- **OSI 5 类安全服务**：鉴别、访问控制、数据机密性、数据完整性、抗抵赖
- **常见攻击**：SQL 注入、XSS、CSRF、DDoS、中间人、重放、社会工程

### §11 知识产权（4.4% ≈ 3 题/年，🔥性价比最高）

- 🔥**著作权归属**（背熟这段就 100% 拿分）：
  - **职务作品**：单位职务→单位；一般职务→个人（单位 2 年优先使用权）
  - **委托作品**：合同约定归谁，**无约定归受托方（开发方）**
  - **合作作品**：共同享有
  - **雇佣关系**：归单位
  - **非职务作品**：归个人
- **著作权保护期**：自然人终身+50 年；法人首次发表后 50 年；软件著作权 50 年
- **专利期**（🔥 2021 修订）：发明 **20 年**、实用新型 **10 年**、外观设计 **15 年**（原 10 年）
- **商标**：注册后 **10 年**，可续展
- **专利授予**：先申请原则（非先发明）
- **商业秘密**：不受期限，公开即失效
- **著作权自动产生**：作品完成即享有，登记非必需

### §10 未来信息综合技术（4.6% ≈ 5 题/年，新大纲重点）

- **官方 6 项**：CPS、AI、机器人、边缘计算、数字孪生、云计算大数据
- **CPS 3C**：Computation、Communication、Control
- **边缘 vs 云**：边缘低延迟/本地；云集中/弹性/大算力
- **数字孪生 5 能力**：描述、诊断、预测、决策、优化
- **云服务模型**：IaaS / PaaS / SaaS
- **云部署模型**：公有 / 私有 / 混合 / 社区
- **大数据 5V**：Volume、Velocity、Variety、Value、Veracity
- **AI 分层**：应用 / 算法 / 算力 / 数据
- **机器学习**：监督、无监督、半监督、强化
- **深度学习**：CNN 图像、RNN/LSTM 序列、Transformer 大模型
- **区块链**：去中心化、不可篡改、共识（PoW/PoS/PBFT）
- **5G 三大场景**：eMBB、URLLC、mMTC
