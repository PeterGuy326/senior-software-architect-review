# 论文主题 11 · 企业应用集成（EAI）

## 历年出题角度

- 论企业应用集成（EAI）技术
- 论异构系统集成方案
- 论数据集成与交换

## 一、核心理论

### EAI 四个层次

1. **表示集成**（Portal、界面集成）
2. **数据集成**（ETL、数据仓库）
3. **控制集成 / 应用集成**（API、ESB）
4. **业务流程集成**（BPM、工作流）

### 集成模式（Hohpe）

| 模式 | 特点 |
|---|---|
| **文件传输** | 简单、异步、粒度粗 |
| **共享数据库** | 紧耦合 |
| **远程调用**（RPC） | 同步、耦合 |
| **消息传递**（MQ） | **解耦、异步、推荐** |

### ETL vs ELT

- **ETL**：传统数仓，转换在入库前
- **ELT**：大数据时代，原始入湖后再处理

### 主流技术

- **消息中间件**：Kafka / RabbitMQ / RocketMQ
- **ESB**：MuleSoft / WSO2
- **工作流 / BPM**：Activiti / Camunda
- **数据集成**：Kettle / DataX / Flink CDC

### 模拟论文题 1 · 论企业应用集成（EAI）的方法与实践

**【完整题目】**（约 410 字）

大型企业经过多年信息化建设，往往拥有 ERP、CRM、HR、OA、财务、供应链、营销等数十套异构业务系统，这些系统由不同厂商、不同技术栈、不同时期建设，形成严重的"数据孤岛"和"业务断点"。企业应用集成（EAI，Enterprise Application Integration）通过表示集成（门户/SSO）、数据集成（ETL/数据仓库）、应用集成（API/ESB/MQ）、业务流程集成（BPM）四个层次，系统化解决跨系统协同问题。Hohpe 在《Enterprise Integration Patterns》中归纳了文件传输、共享数据库、远程调用、消息传递四种主流集成模式，业界普遍推荐**消息传递**模式实现解耦异步。同时主数据管理（MDM）作为集成成败的关键，统一客户、产品、组织等核心数据，是企业数字化的基石。

#### 一、项目背景（350 字提纲）

- **业务背景**：集团 25 套异构系统，跨系统协作困难
- **团队规模**：30 人（架构 4 + 集成开发 18 + 数据治理 5 + 业务 BA 3）
- **关键质量属性**：可集成性、解耦性、可观测性、一致性
- **业务约束**：合规审计、跨部门协作、不影响存量业务

#### 二、核心理论（400 字提纲）

- EAI 四层次：
  - 表示集成（Portal / SSO / iframe）
  - 数据集成（ETL / 数仓 / MDM）
  - 应用集成（API / ESB / MQ）
  - 业务流程集成（BPM / 工作流）
- Hohpe 集成模式：
  - 文件传输（简单异步粒度粗）
  - 共享数据库（紧耦合）
  - 远程调用（同步耦合）
  - 消息传递（解耦异步**推荐**）
- ETL vs ELT：传统 vs 大数据
- 主流技术：Kafka/RabbitMQ/RocketMQ、MuleSoft/WSO2、Activiti/Camunda、Kettle/DataX/Flink CDC

#### 三、实践论述（1500 字提纲，分 5 节）

##### 3.1 表示层集成
- 单点登录 SSO（CAS + LDAP），统一身份
- 企业门户 + iframe 集成 5 个主要业务系统
- 量化：登录次数 5→1、用户感知 +30%

##### 3.2 数据层集成 + MDM
- Kettle ETL 抽取 + 转换 + 装载到企业数仓
- Flink CDC 实时同步关键业务数据
- MDM 主数据管理：客户主数据 / 产品主数据 / 组织主数据
- 数据质量规则 200+，每日跑批 + 异常告警
- 量化：数据一致率从 85% 提升至 99.5%

##### 3.3 应用层集成 + 消息总线
- API Gateway（Kong）统一鉴权 + 限流 + 路由
- Kafka 集群（10 节点）作为企业级消息总线
- 集成模式选型：以消息传递为主、RPC 为辅
- 量化：日处理 1 亿条消息、平均延迟 100ms

##### 3.4 流程层集成 + BPM
- Camunda BPMN 引擎，编排跨系统审批流
- 典型流程：采购申请 → 财务审批 → 供应链下单 → 入库 → 付款
- BPMN 2.0 标准 + 业务规则 DMN
- 量化：流程数字化覆盖 80%、审批周期 5 天→1 天

##### 3.5 风险与应对（必有）
- 风险 1：MDM 数据冲突 → 数据治理委员会 + 仲裁机制
- 风险 2：消息丢失 → 事务消息 + 死信队列 + 对账
- 风险 3：跨系统排错难 → SkyWalking 全链路追踪 + Trace ID 贯通

#### 四、总结与展望（250 字提纲）

- 项目结果：接口 300→50、联动 T+1→秒级、上线 4m→1m、数据一致率 99.5%
- 经验教训：①消息传递是首选 ②MDM 是集成成败关键 ③全链路追踪是排错基础
- 未来演进：iPaaS 集成平台、Event Mesh、AIOps 异常预测

### 模拟论文题 2 · 论数据集成与主数据管理在企业数字化中的应用

**【完整题目】**（约 410 字）

随着企业数字化转型深入，数据已成为继土地、劳动力、资本之后的第五大生产要素。然而许多企业的数据散落在 ERP、CRM、HR、营销、客服等数十套系统中，存在**口径不一、定义冲突、质量参差、更新延迟**等顽疾，严重制约数字化决策。数据集成（Data Integration）与主数据管理（MDM，Master Data Management）正是解决这一难题的核心手段：数据集成通过 ETL/ELT、CDC 实时同步、数据虚拟化等技术将多源数据汇聚到企业数据中心；MDM 则通过建立"客户、产品、组织、员工"等核心实体的唯一可信版本（Golden Record）以及配套的数据治理流程，确保企业数据资产的一致性、完整性、准确性。在金融、零售、制造等行业，MDM 已成为数据中台的核心组件。

请围绕"**论数据集成与主数据管理（MDM）的应用**"论述以下三个问题：

1. **概要叙述**你参与设计与开发的软件项目，以及你担任的主要工作（约 300 字应答）。
2. **简要说明**数据集成模式（ETL/ELT/CDC/虚拟化）以及 MDM 的核心理念与治理流程（约 400 字应答）。
3. **详细论述**你在项目中如何系统化推进数据集成与 MDM、应对治理挑战、量化业务收益（约 1500-1800 字应答）。

**【提纲式参考答案】**（约 1400 字提纲）

#### 摘要框架（300 字模板）

"我于 {2023} 年牵头 {零售集团 / 银行 / 制造企业} 数据中台建设，担任 {数据架构师}。集团下 {18 套源系统 / 客户主数据 5000 万条 / 产品主数据 100 万条}。原状态客户重复率 {15%}、产品口径冲突、报表数据不一致。本文论述数据集成 + MDM 落地：Flink CDC + DataX 实时/批量集成、Informatica MDM 建立 Golden Record、200+ 数据质量规则、数据治理委员会 + DataOps。最终客户重复率降至 0.5%、报表一致性 99.8%、分析时效从 T+3 提升到 T+0、数据资产沉淀 1500 张表。"

#### 一、项目背景（350 字提纲）

- **业务背景**：集团 18 套源系统，数据孤岛严重影响数字化决策
- **团队规模**：35 人（数据架构 4 + ETL 开发 12 + 数据治理 8 + BA 8 + 数据科学家 3）
- **关键质量属性**：一致性、完整性、准确性、时效性
- **业务约束**：合规（PII 保护）、跨部门协作、可审计

#### 二、核心理论（400 字提纲）

- 数据集成模式：
  - **ETL**（传统数仓，转换在前）
  - **ELT**（大数据/湖，原始入库后转换）
  - **CDC**（变更数据捕获，Debezium/Canal/Flink CDC）
  - **数据虚拟化**（不复制数据，统一查询）
- MDM 核心：
  - 主数据识别（客户/产品/组织/员工）
  - Golden Record 唯一可信版本
  - 数据质量规则（完整性/准确性/一致性/唯一性/及时性）
  - 数据治理流程（采集/清洗/匹配/合并/分发）
- 数据治理：DAMA-DMBOK 11 大职能（治理/架构/建模/存储/安全/集成/文档/参考/数仓/MDM/质量）

#### 三、实践论述（1500 字提纲，分 4 节）

##### 3.1 数据集成层
- 离线 ETL：DataX 每日 T+1 全量同步（小表）+ 增量同步（大表）
- 实时 CDC：Flink CDC 订阅 18 个源系统 binlog
- 数据虚拟化：Presto 联邦查询无须落盘的报表
- 量化：日同步 50TB、实时延迟 < 5 秒、数据时效 T+3→T+0

##### 3.2 MDM 平台建设
- 主数据范围：客户、产品、组织、员工、供应商
- 唯一识别：客户基于 Mobile + 身份证哈希、产品基于 SPU 编码
- 匹配规则：精确匹配 + 模糊匹配（Levenshtein 距离）
- Golden Record 合并：按数据源置信度加权
- 量化：客户去重 5000 万→4250 万（重复率 15%→0.5%）

##### 3.3 数据质量 + 治理
- 200+ 数据质量规则：完整性 / 准确性 / 一致性 / 唯一性 / 及时性
- 每日跑批 + 异常告警 + 整改追踪
- 数据治理委员会（IT + 业务 + 法务 + 安全）
- 数据血缘 Atlas：可追溯 / 可影响分析
- 量化：质量得分 70→95、整改 SLA 24h

##### 3.4 风险与应对（必有）
- 风险 1：业务方不愿配合主数据规范 → KPI 对齐 + 高层背书
- 风险 2：CDC 漏数据 → 全量对账 + GAP 检测
- 风险 3：PII 数据合规 → 脱敏 + DLP + 数据分级

#### 四、总结与展望（250 字提纲）

- 项目结果：客户重复率 15%→0.5%、报表一致 99.8%、时效 T+3→T+0、表 1500 张
- 经验教训：①MDM 是数据集成的灵魂 ②数据质量是治理出来的不是开发出来的 ③业务参与是 MDM 成功关键
- 未来演进：DataMesh 数据网格、AIGC 数据资产推荐、湖仓一体 Iceberg
