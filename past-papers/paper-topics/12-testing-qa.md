### 测试方法

- **黑盒**：等价类、边界值、因果图、判定表、场景法

### 非功能测试

- **性能**（JMeter / Gatling）
- **安全**（SonarQube / OWASP ZAP）
- **兼容性**（BrowserStack）
- **可用性**（用户体验测试）
- **混沌工程**（ChaosBlade / Chaos Monkey）

### CI/CD 测试左移右移

- **左移**：开发早期引入测试（TDD/BDD、静态扫描）
- **右移**：生产监控、A/B、全链路压测

- **过程**：CMMI / ISO 9001
- **标准**：ISO 25010（8 质量特性）

### 模拟论文题 1 · 论自动化测试体系与质量左移右移的实践

**【完整题目】**（约 410 字)

随着敏捷开发与 DevOps 的普及，软件交付节奏从月级、周级加速到日级甚至小时级，传统"开发完成后再集中测试"的模式已无法适应快速迭代的需求。Mike Cohn 提出的**测试金字塔**（单元 70% + 集成 20% + UI 10%）为自动化测试体系提供了清晰的策略指引，强调底层测试覆盖更广、运行更快、维护更稳。同时**质量左移**（Shift-Left）将测试前置到开发早期——TDD/BDD、静态扫描、单元测试覆盖率门禁，**质量右移**（Shift-Right）则将质量保障延伸到生产环境——监控告警、A/B 测试、全链路压测、混沌工程。CI/CD 流水线作为载体，配合 SAST/DAST/IAST 安全测试、性能测试（JMeter/Gatling）、混沌工程（ChaosBlade/Chaos Mesh）等工具，共同构成现代质量保障体系。

### 模拟论文题 2 · 论软件质量保证体系与持续质量改进

**【完整题目】**（约 410 字）

软件质量保证（SQA，Software Quality Assurance）不等于测试，而是涵盖**过程、标准、度量、改进**四个维度的系统化工程。CMMI 五级成熟度模型为研发过程管理提供了演进路径——从"初始（无序）"到"管理（项目级）"、"已定义（组织级）"、"量化管理（可度量）"、"持续优化（量化改进）"。ISO 25010 软件质量模型定义了八大质量特性——功能适合性、性能效率、兼容性、易用性、可靠性、安全性、可维护性、可移植性，是质量度量的标准。质量改进则遵循 PDCA（计划-执行-检查-改进）循环，配合根因分析（RCA、5-Why、鱼骨图）系统化解决质量问题。在企业实践中，质量保证体系往往与 DevOps 融合形成 DevSecOps，通过自动化质量门禁实现"质量内建"。

请围绕"**论软件质量保证体系**"论述以下三个问题：

1. **概要叙述**你参与设计与开发的软件项目，以及你担任的主要工作（约 300 字应答）。
2. **简要说明** CMMI、ISO 25010 八大特性、PDCA 改进循环以及主流度量指标（约 400 字应答）。
3. **详细论述**你在项目中如何系统化建设 SQA 体系、推进持续改进、量化质量提升（约 1500-1800 字应答）。

**【提纲式参考答案】**（约 1400 字提纲）

#### 摘要框架（300 字模板）

"我于 {2023} 年牵头 {SaaS 平台 / 银行系统 / 制造软件} 的质量保证体系升级，担任 {SQA 负责人}。组织 {200 人研发 / 18 个产品线}。原状态 CMMI 二级、缺陷密度 1.5/KLOC、客户投诉率高。本文论述系统化质量保证：基于 ISO 25010 八大特性建立质量度量、CMMI 三级关键过程域落地、PDCA 月度改进循环、RCA 根因分析。1 年后达到 CMMI 三级、缺陷密度降至 0.3/KLOC、客户满意度 +35%、过程一致性 90%+。"

#### 一、项目背景（350 字提纲）

- **业务背景**：18 个产品线质量参差不齐，过程不一致
- **团队规模**：SQA 团队 12 人 + 各产品线 QA 50 人
- **关键质量属性**：过程一致性、可度量性、持续改进能力
- **业务约束**：3 年内达到 CMMI 三级、客户合规要求

#### 二、核心理论（400 字提纲）

- CMMI 五级：初始 → 管理 → 已定义 → 量化管理 → 持续优化
- CMMI 关键过程域 KPA（三级 11 个）：需求开发、技术解决、产品集成、验证、确认、组织过程焦点等
- ISO 25010 八大质量特性：功能适合性 / 性能效率 / 兼容性 / 易用性 / 可靠性 / 安全性 / 可维护性 / 可移植性
- PDCA 循环：Plan-Do-Check-Act
- RCA 根因分析：5-Why、鱼骨图、Pareto 图
- 质量度量：缺陷密度 < 0.5/KLOC、覆盖率 > 80%、逃逸率 < 1%、客户满意度 NPS

#### 三、实践论述（1500 字提纲，分 4 节）

##### 3.1 过程标准化（CMMI 三级落地）
- 11 个关键过程域文档化
- 流程模板：需求 / 设计 / 编码 / 测试 / 上线 / 运维
- 评审制度：方案评审 + 代码评审 + 上线评审
- 量化：过程一致性 60%→90%

##### 3.2 质量度量（ISO 25010）
- 8 大特性逐一定义度量指标
- 工具：SonarQube（可维护性）+ JMeter（性能）+ ZAP（安全）+ NPS（易用性）
- 月度质量看板，全员可见
- 量化：质量得分 65→88

##### 3.3 持续改进（PDCA + RCA）
- Plan：每月质量目标 + 改进措施
- Do：执行改进项目（覆盖率提升、缺陷预防、根因消除）
- Check：每月质量复盘 + 趋势分析
- Act：固化为流程标准
- RCA：每个 P0/P1 故障必做 5-Why + 行动项追踪
- 量化：根因消除 80%、复盘行动项闭环率 95%

##### 3.4 风险与应对（必有）
- 风险 1：流程僵化 → 持续精简 + 业务方反馈
- 风险 2：度量造假 → 工具自动采集 + 抽样审计
- 风险 3：改进流于形式 → 高层背书 + KPI 挂钩

#### 四、总结与展望（250 字提纲）

- 项目结果：CMMI 二级→三级、缺陷密度 1.5→0.3/KLOC、NPS +35%、过程一致 90%
- 经验教训：①SQA 不等于测试 ②度量是改进的前提 ③RCA 是真正消除问题
- 未来演进：CMMI 四级（量化管理）、AI 缺陷预测、DevSecOps 全面落地
