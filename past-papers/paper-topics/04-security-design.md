# 论文主题 04 · 系统安全性与保密性设计

## 历年出题角度

- 论系统安全架构设计及其应用（**高频**）
- 论软件系统中的信息安全
- 论零信任架构在 XX 系统的应用

## 一、核心理论

### CIA 三要素

- **C**onfidentiality 保密性
- **I**ntegrity 完整性
- **A**vailability 可用性

### 纵深防御 5 层

1. 网络层
2. 主机层
3. 应用层
4. 数据层
5. 管理 / 审计层

### STRIDE 威胁建模

| 威胁 | 含义 | 对策 |
|---|---|---|
| **S**poofing | 身份伪造 | 认证（SSO + MFA） |
| **T**ampering | 数据篡改 | 完整性校验（HMAC） |
| **R**epudiation | 抵赖 | 日志 + 数字签名 |
| **I**nformation Disclosure | 信息泄露 | 加密（TLS + AES） |
| **D**oS | 拒绝服务 | 限流 + DDoS 清洗 |
| **E**levation of Privilege | 权限提升 | 最小权限 + RBAC |

### 密码学基础

- 对称：DES / 3DES / **AES** / 国密 **SM4**
- 非对称：**RSA** / ECC / 国密 **SM2**
- Hash：MD5 / SHA-256 / 国密 **SM3**
- 数字签名：私钥签 + 公钥验

### 等保 2.0

- 五级分类（一般系统**三级**起）
- 10 大技术要求（物理 / 网络 / 边界 / 计算环境 / 管理中心 + 5 项管理）

## 三、实战数据

- 等保等级：**三级**（政企标配）
- 加密算法：AES-256、TLS 1.3、SM2/3/4
- 认证强度：**SSO + MFA**
- 审计覆盖：**100% 关键操作**
- 漏洞修复 SLA：高危 **24h**，中危 **7 天**

## 四、万能句式

- "针对等保三级合规要求，采用纵深防御策略，从**网络、主机、应用、数据、审计**五层建立防护"
- "通过 **STRIDE 威胁建模**识别出 X 类高危威胁，逐一设计对策"
- "关键数据采用 **AES-256 + 密钥管理 KMS**，传输层 TLS 1.3"
- "实施**最小权限 + 职责分离**，通过 **RBAC** 控制访问"

## 五、避坑点

| ❌ | ✅ |
|---|---|
| 只讲加密算法 | **分层防御**体现架构思维 |
| 忽视合规 | **等保 / GDPR / SOX** 明确写 |
| 无审计追溯 | 审计日志是监管重点 |
| 方案一刀切 | **数据分级**，敏感级别不同方案不同 |

### 模拟论文题 1 · 论纵深防御理念在系统安全架构设计中的应用

**【完整题目】**（约 420 字）

随着《数据安全法》《个人信息保护法》《关键信息基础设施安全保护条例》的相继落地，企业信息系统面临的安全合规压力持续加大。传统的"边界防御"已无法应对内部威胁、API 攻击、供应链攻击等新型风险，业界普遍采用纵深防御（Defense in Depth）理念，从网络、主机、应用、数据、审计五层构建多重防线。同时基于 STRIDE 威胁建模识别身份伪造、数据篡改、抵赖、信息泄露、拒绝服务、权限提升六类威胁，并结合 CIA 三要素（保密性、完整性、可用性）、最小权限、零信任等设计原则，形成系统化的安全架构。在金融、政务、医疗等高敏感行业，等保 2.0 三级合规已成为基本要求。

请围绕"**论系统安全架构设计及其应用**"论述以下三个问题：

1. **概要叙述**你参与设计与开发的软件项目，以及你担任的主要工作（约 300 字应答）。

3. **详细论述**你在项目中如何分层落地安全架构、应对何种威胁、最终通过何种合规测评（约 1500-1800 字应答）。

#### 一、项目背景（350 字提纲）

- **业务背景**：政务/金融/医疗 系统，等保三级合规
- **团队规模**：研发 30 人 + 安全 4 人 + 第三方测评机构
- **关键质量属性**：保密性、完整性、可用性、合规性、可审计性
- **威胁面**：互联网暴露、内部员工、第三方供应链

#### 二、核心理论（400 字提纲）

- CIA 三要素：保密性（C）/ 完整性（I）/ 可用性（A）
- 纵深防御 5 层：网络/主机/应用/数据/管理审计
- STRIDE 威胁建模：S 伪造 / T 篡改 / R 抵赖 / I 泄露 / D 拒绝服务 / E 提权
- 密码学：对称（AES/SM4）、非对称（RSA/SM2）、Hash（SHA-256/SM3）、数字签名
- 等保 2.0 五级分类，三级 10 大技术要求
- 零信任原则：永不信任、始终验证

#### 三、实践论述（1500 字提纲，分 5 节按层展开 + 风险）

##### 3.1 网络层
- 防火墙 + WAF（拦截 SQL 注入/XSS/CC）+ DDoS 清洗
- VPC 分区 + 安全组最小开放
- 量化：日均拦截恶意请求 50 万次

##### 3.2 主机层
- HIDS（OSSEC/青藤）+ 基线加固 + 漏扫
- 容器镜像扫描（Trivy）
- 量化：CVE 修复 SLA 高危 24h

##### 3.3 应用层
- SSO（CAS/Keycloak）+ MFA（TOTP/U-Key）
- RBAC + 最小权限 + 职责分离
- 输入校验 + CSP + CSRF Token
- API 网关限流 + 鉴权

##### 3.4 数据层
- 传输：TLS 1.3 全链路
- 存储：AES-256（敏感字段）+ 数据库 TDE
- 脱敏：手机号/身份证 *** 显示
- DLP：禁止外发敏感字段
- 密钥管理：KMS（HSM 硬件加密机）

##### 3.5 审计 + 风险应对
- SIEM 集中日志（Splunk/ELK + 安全规则）
- 全链路审计：100% 关键操作可追溯
- 定期红蓝对抗 + 渗透测试
- 风险 1：内鬼数据导出 → 4-eye 审批 + DLP
- 风险 2：第三方 SDK 漏洞 → SCA + 供应链清单
- 风险 3：API 滥用 → API 行为分析 + 异常告警

#### 四、总结与展望（250 字提纲）

- 项目结果：等保三级通过 / 零重大安全事件 / 漏洞高危 24h 闭环
- 经验教训：①安全是系统工程不是补丁工程 ②合规驱动 + 实战验证缺一不可 ③零信任要从架构层落地
- 未来演进：零信任 SASE、AIGC 安全、机密计算 TEE
