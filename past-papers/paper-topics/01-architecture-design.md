## 一、核心理论（400 字以内）

### 1. 软件架构定义

软件架构（Software Architecture）是系统的**基本结构**，包括软件元素、元素之间的关系、以及二者的特性。架构为软件系统提供了结构、行为和属性的高级抽象。

### 2. 主流架构风格

- **数据流**：批处理、管道—过滤器
- **调用—返回**：主程序—子程序、OO、层次式、C/S
- **独立构件**：进程通信、事件驱动（发布—订阅）
- **虚拟机**：解释器、规则系统
- **数据中心**：数据库仓库、黑板
- **闭环控制**：过程控制

### 3. 4+1 视图模型

逻辑视图、开发视图、进程视图、物理视图 + 场景视图

### 4. ABSD 过程（6 步）

架构需求 → 架构设计 → 文档化 → 复审 → 实现 → 演化

### 模拟论文题 1 · 论软件架构风格在企业级业务系统中的应用

**【完整题目】**（约 400 字）

随着企业数字化转型的深入，业务系统的规模、复杂度与变化速度均显著提升，对软件架构提出了高并发、高可用、高可扩展的多重诉求。软件架构风格（Architectural Style）作为对一类系统结构和交互方式的高层抽象，是架构师在设计早期最关键的决策对象之一。常见的架构风格包括数据流、调用-返回（分层、面向对象、客户/服务器）、独立构件（事件驱动、发布-订阅）、虚拟机（解释器、规则系统）、数据中心（黑板、数据仓库）等多种类型。架构师必须基于业务规模、质量属性目标、团队能力等多维因素，权衡各风格的优劣，往往采用"分层 + 微服务 + 事件驱动"的混合风格落地。

1. **概要叙述**你参与设计与开发的软件项目，以及你担任的主要工作（约 300 字应答）。

#### 一、项目背景（350 字提纲）

- **业务背景**：3 条业务线（B2C/跨境/线下门店）订单系统数据模型不一致、促销重复开发
- **团队规模**：25 人（架构 2 + 后端 15 + 前端 4 + 测试 3 + 运维 1）
- **关键质量属性**（候选 5 选 3）：性能、可用性、可修改性、一致性、安全性
- **技术挑战**：异构遗留系统、跨业务线库存共享、大促弹性

#### 二、核心理论（400 字提纲）

- 架构定义：元素 + 关系 + 特性
- 5 大经典风格：数据流（管道-过滤器）/ 调用-返回（分层、OO、C/S）/ 独立构件（事件驱动）/ 虚拟机（解释器）/ 数据中心（黑板）
- 风格组合：实践中常用"分层 + 微服务 + 事件驱动"
- 4+1 视图：逻辑/开发/进程/物理 + 场景
- ABSD 6 步：需求 → 设计 → 文档化 → 复审 → 实现 → 演化
- 风格 vs 模式：风格是宏观结构，模式是局部细节

#### 三、实践论述（1500 字提纲，分 4 节）

##### 3.1 风格候选与选型决策
- 候选 1 单体分层：开发简单但发布慢，否决
- 候选 2 SOA+ESB：契约规范但 ESB 单点，否决
- 候选 3 微服务+事件驱动：选中
- 决策点：业务独立性 / 弹性扩展 / 故障隔离

##### 3.2 微服务风格落地（DDD 限界上下文）
- 10 个业务服务 + 5 个基础服务
- gRPC（内部）+ REST（对外）+ RocketMQ（异步）
- Database Per Service 红线
- 量化效果：服务平均 5000 行代码、独立 CI/CD

##### 3.3 事件驱动风格落地
- 订单状态变更走 RocketMQ 事件总线
- 履约/对账/通知服务订阅事件，松耦合
- 解决跨服务一致性：本地消息表 + TCC 补偿

##### 3.4 风险与应对（必有）
- 风险 1：分布式事务复杂 → TCC + 补偿日志 + 对账兜底
- 风险 2：链路过长 P99 飙升 → 多级缓存 + SkyWalking 定位
- 风险 3：促销引擎过热 → 保留单体 + Sentinel 熔断

#### 四、总结与展望（250 字提纲）

- 项目结果：QPS 6.2 万、P99 178ms、可用性 99.995%、零 P0 故障
- 经验教训：①风格不是教条，混合落地是常态 ②保留合理单体避免过度工程 ③ATAM 闭环验证决策
- 未来演进：Istio 服务网格 + GitOps + Argo CD 提升变更效率
