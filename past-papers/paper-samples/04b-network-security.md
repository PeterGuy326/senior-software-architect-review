# 范文 04b · 论网络安全体系设计与零信任架构应用

> **题目（对标真题）**：2014 年 · 论网络安全体系设计 / 2021 年 · 论系统安全架构设计及其应用
> **案例改编**：某三甲医院 HIS / EMR 系统等保 2.0 升级 + 零信任改造（2022-2023）
> **字数**：约 3000 字
> **与范文 04 的差异**：04 是政务大数据平台、聚焦"信息保密"五层防御；本文是医疗 HIS / EMR 系统、聚焦"**网络安全体系（等保 2.0）+ 零信任架构落地**"，强调网络层与零信任结合。

## 摘要（约 320 字）

2022 年 6 月，我所在公司中标某省级三甲医院（**3000 张床位、日门诊 1.2 万人次、年诊疗量 380 万人次**）的"HIS（医院信息系统）+ EMR（电子病历）+ PACS（影像）核心系统等保 2.0 升级 + 零信任改造"项目，承担**网络安全体系重构、零信任架构落地、个人健康信息保护、安全运营中心（SOC）建设**四大任务。系统涉及**患者隐私（身份证、病历、基因检测）+ 医保结算（年医保金额 28 亿元）+ 医生处方权限 + 远程会诊**等高敏感场景，**任何一次数据泄露都会触发卫健委通报、医保局核查、患者集体诉讼三重打击**。我作为该项目的**安全架构师**，主导了网络安全体系与零信任架构的整体方案。项目历时 **15 个月**，团队规模 **24 人**。

本文结合该项目，论述网络安全体系与零信任架构的应用。首先介绍项目背景与关键质量属性，然后阐述等保 2.0 五大类、网络安全模型、零信任 SDP 架构等核心理论，最后重点展开**等保 2.0 网络安全防护、零信任 SDP 架构落地、个人健康信息全生命周期保护、SOC 安全运营**四个关键环节。项目于 **2023 年 9 月**通过等保三级测评，关键指标全部达标：**等保 2.0 三级测评一次通过**、**零信任覆盖 100% 内部访问**、**个人健康信息零泄露**、**外部攻击日均拦截 12 万次**、**安全事件 MTTR 从 4 小时降到 25 分钟**、**通过卫健委 + 医保局两次专项检查均无重大问题**。

## 一、项目背景（约 350 字）

医疗行业是信息泄露事件的"重灾区"。2021 年某沿海省份三甲医院曾发生 50 万患者电子病历被黑产脱库事件，被卫健委公开通报、医院被罚 380 万元、院长被问责。本项目所在医院作为该省核心三甲，**患者隐私 + 医保资金 + 医生处方权 + 远程会诊**多重敏感数据集中。原网络安全体系存在三大顽疾：**边界过度信任**（内网即安全的传统思维，一旦边界被突破横向扩散无阻）、**身份与设备身份验证薄弱**（大量医生用同一个共用账号登录、移动设备未管控）、**个人健康信息防护不到位**（病历查询无脱敏、医生跨科室越权访问普遍）。同时**等保 2.0 三级**是医疗系统的强制合规要求，未通过测评影响医院评级。

项目启动时，我作为安全架构师主导设计工作。关键质量属性包括：**合规性**（等保 2.0 三级 + 卫健委 + 医保局 + 个保法）、**纵深防御性**（边界 + 内部 + 数据 + 行为多层防护）、**最小权限**（职责分离 + 按需授权 + 即时回收）、**可审计性**（所有患者数据访问 100% 可追溯到经办人）、**业务连续性**（安全改造不影响日常诊疗）、**用户体验**（医生不能因安全增加操作复杂度）。团队由 24 人组成，含安全架构 4 人、网络与零信任 8 人、应用安全 5 人、数据安全 4 人、SOC 运营 3 人，计划 15 个月分三阶段（设计 3 月 + 建设 9 月 + 运营 3 月）落地。

## 二、核心理论（约 360 字）

**网络安全（Cybersecurity）** 围绕信息系统的**保密性 C、完整性 I、可用性 A**（CIA 三要素）展开防护。**等保 2.0（GB/T 22239-2019）** 是中国信息安全等级保护强制标准，将系统按重要性分五级（医疗系统为三级）。**等保 2.0 技术要求**分五大类：

| 类别 | 关键控制项 |
|---|---|
| **物理与环境安全** | 机房门禁、视频监控、防雷防火、电磁防护 |
| **网络通信安全** | 网络架构（区域划分、边界防护）、通信传输（加密、完整性）、可信验证 |
| **区域边界安全** | 边界防护（防火墙、IPS）、访问控制、入侵防范、恶意代码防护、安全审计 |
| **计算环境安全** | 身份鉴别、访问控制、入侵防范、数据完整性、数据保密性、个人信息保护 |
| **安全管理中心** | 系统管理、审计管理、安全管理、集中管控（SOC） |

**零信任架构（Zero Trust Architecture，NIST SP 800-207）** 颠覆传统"内网即安全"假设，**核心原则**："**永不信任、始终验证（Never Trust, Always Verify）**"。三大支柱：**身份**（用户 + 设备）、**最小权限**（按需授权 + 持续评估）、**微隔离**（细粒度访问控制）。**SDP（Software Defined Perimeter，软件定义边界）** 是零信任主流落地形态，由**控制平面（IH 发起者 + AH 接收者 + Controller 控制器）** 与**数据平面**分离。**Google BeyondCorp** 是零信任标杆案例。

**个人信息保护**遵循**最小化、明确目的、知情同意、安全保护、可追溯**五原则。医疗领域额外受 **HIPAA（美国）/ 个保法 + 数据安全法（中国）** 约束。**国密算法（SM2/SM3/SM4）** 在医疗场景为强制使用。上述理论构成了我在医院安全设计的方法论基础。

## 三、安全架构实践（约 1600 字）

### 3.1 等保 2.0 网络安全防护体系

按等保 2.0 三级要求，重构"**四区三层**"网络安全架构。

**四区**：**互联网区**（对外服务暴露区）、**DMZ 区**（API 网关 + WAF）、**应用区**（HIS/EMR/PACS 等业务系统）、**数据区**（数据库 + 存储）。每区之间部署**下一代防火墙 NGFW（深信服 AF）+ IPS 入侵防御系统**，严格按白名单放行，**默认拒绝所有未授权流量**。

**三层防护**：**外层抗 DDoS**（接入省电信清洗中心，可抗 100Gbps 攻击）；**中层 WAF**（绿盟 NGAF 集群，防 OWASP Top 10：SQL 注入、XSS、CSRF、文件上传等；日均拦截恶意请求 12 万次）；**内层 IDS**（启明星辰天阗）联动**威胁情报平台**（微步在线），新发现 IOC 自动同步策略。

**网络分段**采用 **VXLAN + 微隔离**：每个业务系统独立 VLAN，跨 VLAN 访问必经防火墙；服务器内部通过 **东西向微隔离（绿盟 ICEBERG）** 实现 Pod 级访问控制，**横向移动攻击面缩减 90%**。

**通信加密**：所有外部访问强制 **TLS 1.3 + 国密 SM2 证书**（双证书模式：商用 + 国密同时支持）；内部服务间调用全部走 **mTLS 双向认证**，证书由 **国密 PKI 体系**统一签发管理。

### 3.2 零信任 SDP 架构落地

零信任是项目最具创新性的环节。建设了基于 **NIST SP 800-207 + Google BeyondCorp 思路** 的 **SDP 架构**：

**身份层（Who + What）**：每个访问主体的身份由"**用户身份 + 设备身份**"双维度构成。用户身份用 **Keycloak SSO + OIDC**，所有医生/护士/管理员统一身份；**MFA 强制** 包含**国密 SM2 证书 + 动态口令 + 人脸识别**三因素，敏感场景（如开处方、查 VIP 病历）额外推送审批。设备身份用 **设备证书 + 健康检查（杀软状态、补丁版本、磁盘加密、合规配置）**，不健康设备一律拒绝接入。BYOD（医生自带手机）必须安装**MDM 移动设备管理**客户端方可接入医院内网。

**控制平面（Policy）**：基于 **OPA（Open Policy Agent）+ 自研策略引擎** 实现**动态最小权限**：访问决策不仅看"用户角色"还看"上下文"（地点、时间、设备健康度、行为基线）。例如普通医生白天院内访问 EMR 自由通过，夜间从院外访问触发额外验证 + 严格脱敏 + 全量审计。

**数据平面（SDP Gateway）**：所有内部应用访问必经 **SDP Gateway（自研 + ZTNA 厂商集成）**，传统 VPN 全面下线。SDP Gateway 负责"**先验证身份后建立隧道**"——访问发起前应用对外完全不可见（隐身原则），验证通过后才动态建立加密隧道。

**持续评估（Continuous Verification）**：用户行为基于 **UEBA（User and Entity Behavior Analytics）** 持续评分，异常行为（如同一账号短时跨地登录、批量下载病历）触发**会话即时熔断 + 风控告警**。

零信任改造后**内部访问 100% 经过身份 + 设备双验证**、**横向移动攻击在内部测试中 100% 被拦截**、**远程办公医生体验由"开 VPN 等 30 秒"提升至"打开应用即用"**。

### 3.3 个人健康信息全生命周期保护

医疗数据是项目核心战场。建设"**采集 + 存储 + 使用 + 共享 + 销毁**"全生命周期防护：

**采集阶段**：所有数据采集必须有**明确目的与法律依据**，知情同意（电子签名）入库。**存储阶段**：按敏感级分类（公开 / 内部 / 敏感 / 核心隐私），**敏感与核心强制 SM4 字段级加密**（KMS 集中托管 + 90 天自动轮换密钥），**数据库 TDE 透明加密 + 磁盘 LUKS 加密**双层。

**使用阶段**核心是**动态脱敏**：基于角色、场景、上下文动态返回不同脱敏级别。例如查询患者 `张某某` 病历，普通护士看到 `身份证 1101**********1234 / 手机 138****1234 / 病历摘要`，主治医生看到全量明文 + 操作全审计，挂号员只看到 `张某某 / 性别 / 年龄段` 三个字段。脱敏由**自研脱敏中间件**统一拦截 SQL 与 API 响应实施。

**共享阶段**：跨医院会诊数据走**专用医联体加密通道 + 数据水印**，泄露事件可追溯到具体医院与具体经办人。**销毁阶段**：归档数据按法规保留 30 年（住院 + 门诊大病历），过期数据**多次覆写 + 加密密钥销毁**双保险，第三方安全公司出具销毁证明。

**个人信息保护影响评估（PIA）**：每个新业务系统上线前强制做 PIA，识别潜在隐私风险并落实减缓措施。

### 3.4 SOC 安全运营中心

技术再强，**没有 7×24 运营也是摆设**。建设 **SOC 安全运营中心**：3 人值班 × 三班倒 + 安全架构师 On-Call。

**SIEM 平台**用 **Splunk Enterprise**，汇聚网络设备 + 主机 HIDS + 应用日志 + WAF + IDS + 业务审计共**日均 22 TB 安全日志**，配置**85 条威胁检测规则**（如：批量下载病历、跨科室越权、夜间异地登录、SQL 异常模式、敏感数据外发）。**SOAR（安全编排自动化响应）** 自动化处置 70% 的中低风险告警（如：自动封 IP、自动锁账号、自动隔离主机），让 SOC 人员聚焦高风险告警。

**威胁狩猎（Threat Hunting）** 月度主动开展，基于威胁情报与 ATT&CK 框架主动找已渗透但未触发告警的威胁。**蓝军演练**季度一次，红队由外部专业团队扮演 APT 攻击者，蓝队（SOC + IT）按预案响应。**应急预案**覆盖 **18 类典型场景**（脱库、勒索、内鬼、APT、DDoS 等），所有预案桌面演练 + 实战演练双重验证。

**安全事件 MTTR 从 4 小时降到 25 分钟**、**告警响应及时率从 65% 提升到 99.6%**。

风险应对：**等保整改与日常运维冲突** → 改造分阶段 + 业务低峰期实施；**零信任体验下降** → 用户体验测试 + 医生反馈快速优化；**MDM 隐私顾虑** → 仅采集合规所需信息 + 隐私政策公示 + 工会沟通；**SOC 人员能力** → 引入外部 MSSP（托管安全服务）补充能力 + 内部持续培训。

## 四、成效与展望（约 260 字）

项目于 2023 年 9 月按计划完成等保三级测评，运行半年实测：**等保 2.0 三级测评一次通过**、**零信任覆盖 100% 内部访问**、**外部攻击日均拦截 12 万次**、**横向移动攻击 0 起**（前一年 18 起）、**个人健康信息零泄露**、**安全事件 MTTR 4h → 25min**、**通过卫健委 + 医保局两次专项检查均无重大问题**、**医生远程办公体验显著提升**，**核心质量目标全部达成**。

回顾项目，我的最大体会是：**网络安全是体系不是单点**——等保 2.0 五大类不是 checklist 而是相互支撑的纵深；**零信任不是产品是理念**——核心是"**永不信任始终验证**"，需要身份 + 设备 + 策略 + 持续评估全套配合；**安全运营是安全的底线**——再好的技术架构没有 SOC 7×24 都是裸奔；**安全与业务可以共赢**——零信任反而提升了医生远程办公体验。

不足在于**AI 在 SOC 的应用**仍较初级，告警噪声仍偏多。下一步规划引入 **AI 驱动 UEBA**（基于行为基线深度学习）、**SOAR 编排自动化升级**、推进**完整身份编织（Identity Fabric）** 进一步提升零信任成熟度。
