# 案例题型 07 · 安全架构分析

> 中频题型，近 5 年偶尔出现，25 分。

## 考点分布

- 识别**安全威胁**（STRIDE）
- 设计**纵深防御**方案（分层）
- **加密**算法选择（对称 / 非对称 / Hash）
- **认证 + 授权**（SSO / MFA / RBAC / ABAC）
- 合规要求（**等保 2.0 / GDPR**）

## 核心理论（必背）

### CIA 三要素

- **C** onfidentiality 保密性
- **I** ntegrity 完整性
- **A** vailability 可用性

### STRIDE 威胁建模

| 威胁 | 含义 | 对策 |
|---|---|---|
| **S**poofing | 身份伪造 | 认证、MFA、证书 |
| **T**ampering | 数据篡改 | HMAC、数字签名 |
| **R**epudiation | 抵赖 | 数字签名、审计日志 |
| **I**nformation Disclosure | 信息泄露 | 加密（TLS/AES）、脱敏 |
| **D**oS | 拒绝服务 | 限流、WAF、DDoS 清洗 |
| **E**levation of Privilege | 权限提升 | 最小权限、RBAC、沙箱 |

### 纵深防御 5 层

1. **网络**：防火墙、WAF、IPS/IDS、DDoS 清洗
2. **主机**：HIDS、基线加固、漏洞扫描
3. **应用**：认证授权、输入校验、CSP、SQL 注入防护
4. **数据**：加密（传输/存储）、脱敏、DLP、KMS
5. **管理 / 审计**：日志审计、SIEM、应急响应

### 加密算法

| 类型 | 特点 | 代表 | 国密 |
|---|---|---|---|
| 对称 | 快、共享密钥 | AES / 3DES | **SM4** |
| 非对称 | 慢、公私钥 | RSA / ECC | **SM2** |
| Hash | 不可逆 | SHA-256 / MD5 | **SM3** |
| 签名 | 私钥签公钥验 | RSA / ECDSA | SM2 |

### 认证与授权

- **认证**（Authentication）：**你是谁**—— 密码、MFA、生物、证书
- **授权**（Authorization）：**你能干啥**—— RBAC / ABAC / ACL
- **SSO**：CAS / OAuth2 / OIDC / SAML
- **MFA**：短信 / TOTP / U2F / 生物

### 等保 2.0

- **5 级**分类（一般系统**三级**起）
- **技术**5 项：物理、网络、边界、计算环境、管理中心
- **管理**5 项：安全管理制度、机构、人员、建设、运维

## 答题模板

### 问题 1：识别威胁（STRIDE 分析）

**套路**：
> 针对系统的【登录 / 支付 / 管理后台 / 数据同步】模块，识别：
> - **S 身份伪造**：弱密码，对策 **MFA + 密码复杂度**
> - **T 数据篡改**：中间人攻击，对策 **TLS 1.3 + HMAC**
> - **I 信息泄露**：日志含敏感，对策 **脱敏 + 访问控制**
> - **D DoS**：暴刷接口，对策 **限流 + 滑动窗口**

### 问题 2：设计纵深防御

**五层标准答案**：
```
网络层：防火墙 + WAF + DDoS 清洗
主机层：HIDS + 基线加固 + 漏扫周期 7 天
应用层：SSO + MFA + RBAC + 输入校验 + CSRF Token
数据层：TLS 1.3（传输）+ AES-256（存储）+ 字段脱敏 + KMS
审计层：全链路日志 + SIEM + 100% 关键操作审计
```

### 问题 3：加密方案

**套路**：
- **传输**：TLS 1.3（强制）
- **存储密码**：**Bcrypt / Scrypt / Argon2**（加盐 + 慢哈希）
- **敏感字段**：**AES-256-GCM**（带认证）
- **密钥**：**KMS 托管 + 定期轮换 90d**
- **身份证 / 手机**：**国密 SM4**（合规要求）

### 问题 4：合规分析

**套路**：
> 本系统属于**等保三级**，需满足：
> - 身份鉴别：**双因素认证**
> - 访问控制：**最小权限 + 职责分离**
> - 安全审计：**100% 关键操作日志 + 6 个月保留**
> - 数据保护：**传输加密 + 存储加密 + 备份加密**
> - 入侵防范：**HIDS + NIDS + 漏洞扫描**

## 万能高分句

- "依据 **STRIDE 威胁建模**，识别出 **6 类威胁**，逐一设计对策"
- "采用**纵深防御**策略，从**网络 / 主机 / 应用 / 数据 / 审计**五层构建防护"
- "核心敏感数据采用 **AES-256-GCM + KMS 密钥轮换**，满足**等保三级**"
- "实施**最小权限 + 职责分离**，基于 **RBAC** 精细化到**菜单 / 按钮 / 字段**级"

## 常见陷阱

| ❌ | ✅ |
|---|---|
| 只讲 HTTPS | 分层防御，**5 层都要覆盖** |
| MD5 存密码 | 必须 **Bcrypt/Scrypt/Argon2** |
| 对称加密公网传 | 对称**配合非对称**交换密钥 |
| 无审计 | 日志 + SIEM **必写** |
| 忽视合规 | **等保 / GDPR** 必须提 |

### 模拟题 1 · 银行核心系统等保三级与 STRIDE 威胁建模（25 分）

**【题干】**（约 820 字）

某城商行启动新一代核心账务系统改造，目标替代原有 IBM 大型机方案。架构师 Y 主导安全架构设计，需通过**等保三级测评**与**人民银行金融科技安全评估**双重审核。团队规模 30 人（含 4 名安全工程师），开发周期 18 个月。

业务规模：账户数 **2000 万**、日均交易 **1500 万笔**、峰值 TPS **8000**、年可用性 **99.99%**、单笔交易 P99 延迟 **< 300ms**。系统覆盖 **柜面、网银、手机银行、ATM、对公、API 开放平台** 6 个渠道。

Y 提交的安全架构核心决策：

1. **网络分区**：按等保三级要求划分 **DMZ 区 / 业务区 / 数据区 / 管理区** 4 个安全域，区间通过下一代防火墙（NGFW）+ Web 应用防火墙（WAF）隔离，关键东西向流量经 IPS 检测；
2. **认证体系**：
   - 柜面/管理员：U-Key 硬件证书 + 动态口令 + 人脸识别**三因素**；
   - 手机银行：手机短信 OTP + 设备指纹 + 生物识别**两因素**；
   - API 开放平台：基于 OAuth 2.0 + JWT，应用方需提交国密 SM2 证书；
3. **授权模型**：核心系统采用 **RBAC + ABAC** 混合，RBAC 控制功能权限（菜单/按钮），ABAC 基于"时间/地点/金额/客户等级"4 属性动态决策；
4. **数据加密**：
   - **传输**：全链路 TLS 1.3，行内对外接口强制 **国密 SSL（SM2/SM3/SM4）**；
   - **存储**：客户敏感字段（身份证、手机、卡号）AES-256 + KMS 主密钥每年轮换；
   - **数据库**：TDE 透明加密（基于国密 SM4）；
5. **密钥管理**：HSM（硬件安全模块）独立机柜部署，主密钥**永不离开 HSM**，业务密钥分级派生；
6. **审计与监控**：全量日志接入 SIEM（如 ArcSight），关键操作 **100% 留痕保存 5 年**，UEBA（用户行为分析）实时告警；
7. **应急响应**：建立 SOC 7×24 监控，重大事件 30 分钟内启动响应，2 小时内提交监管。

Y 计划用 **STRIDE 威胁建模**对核心模块"**网银登录 + 转账"链路进行系统性威胁分析**。

**【小问】**（合计 25 分）

**问 1**（10 分）：针对"网银登录 + 转账"链路，使用 **STRIDE 模型**逐项识别 **6 类威胁**，每类威胁给出**至少 1 个具体场景**和**对应防御措施**（结合本架构具体落地）。

**问 2**（8 分）：本系统采用**等保三级**，请简述等保三级**技术要求 5 项**（物理 / 网络 / 主机 / 应用 / 数据）的核心条款，并说明本架构在**网络安全**和**数据安全**两个维度的合规落地。

**问 3**（4 分）：行内 **国密 SM2 / SM3 / SM4** 算法的用途分别是什么？给出与国际算法（RSA / SHA-256 / AES）的**等价对照**与**性能差异**。

**问 4**（3 分）：客户敏感数据（身份证、卡号）的"**加密 + 脱敏**"双层防护各自解决什么问题？为何不能只选其一？

**【参考答案】**

**问 1**：STRIDE 6 类威胁建模（约 480 字）

| 威胁 | 具体场景 | 防御措施（本架构落地） |
|---|---|---|
| **S - Spoofing 身份伪造** | 攻击者用社工得到的客户密码登录网银，冒充客户发起转账 | ① 强制多因素认证（短信 OTP + 设备指纹 + 生物识别）；② 设备指纹绑定，新设备首次登录强制风控审核；③ API 开放平台用国密 SM2 证书双向认证 |
| **T - Tampering 数据篡改** | 攻击者通过中间人攻击篡改转账报文（金额从 100 → 100000） | ① 全链路 TLS 1.3 + 国密 SSL；② 关键报文国密 SM2 数字签名，服务端验签；③ 数据库写入时计算 HMAC-SM3 摘要，读出比对 |
| **R - Repudiation 抵赖** | 客户事后否认曾发起转账（"我没操作"） | ① 全量操作日志 + SM2 签名（不可抵赖）；② 关键交易回放视频留存（柜面）；③ 时间戳服务（TSA）+ 区块链存证（BCFG），日志保存 5 年 |
| **I - Information Disclosure 信息泄露** | 数据库管理员或运维查询客户敏感字段 | ① 字段级 AES-256 加密 + KMS 主密钥；② 列权限 + 数据脱敏视图（DBA 看到的是 `1101**********0123`）；③ DLP 数据防泄漏，禁止敏感数据外发邮件/U盘 |
| **D - Denial of Service 拒绝服务** | 攻击者用僵尸网络对网银登录接口发起 DDoS（100 万 QPS） | ① 运营商 DDoS 清洗（10G+）；② WAF 七层 CC 防护 + 滑动窗口限流（IP+用户双维度）；③ Sentinel 限流熔断，登录接口 100 QPS/IP，账户级 5 次/分钟 |
| **E - Elevation of Privilege 权限提升** | 普通柜员通过 SQL 注入 / 越权访问获取行长权限 | ① RBAC + ABAC 双重授权，每个 API 接口都做权限校验；② 输入参数白名单 + 预编译 SQL；③ 最小权限原则，柜员账号无 DDL/DML 权限；④ HIDS（如 OSSEC）实时检测异常进程 |

**问 2**：等保三级技术要求与落地（约 350 字）

**等保三级技术要求 5 项**：

| 项目 | 三级核心要求 |
|---|---|
| **安全物理** | 机房 7×24 视频监控 + 双路市电 + UPS + 防火/防水/防雷 |
| **安全通信网络** | 网络分区 + 通信加密 + 通信完整性 + 拨号准入控制 |
| **安全区域边界** | 边界防护（防火墙）+ 访问控制 + 入侵防范（IPS）+ 恶意代码防范 |
| **安全计算环境** | 身份鉴别（双因素）+ 访问控制（最小权限）+ 安全审计 + 入侵防范 + 恶意代码防范 + 数据完整性 + 数据保密性 + 数据备份恢复 + 剩余信息保护 + 个人信息保护 |
| **安全管理中心** | 系统管理 + 审计管理 + 安全管理 三权分立 |

**网络安全合规落地**：
- DMZ / 业务 / 数据 / 管理 4 区物理隔离，符合"网络分区"；
- NGFW + WAF + IPS 三层边界防护，符合"边界防护 + 入侵防范"；
- 全链路国密 SSL，符合"通信加密 + 完整性"；
- 4 区互访通过堡垒机 + 跳板机审计，符合"访问控制"。

**数据安全合规落地**：
- 客户敏感字段 AES-256 + KMS（密钥每年轮换），符合"数据保密性 + 个人信息保护"；
- TDE 透明加密 + 备份加密，符合"数据备份恢复 + 数据完整性"；
- 数据销毁 7 次覆写 + 物理粉碎，符合"剩余信息保护"；
- DLP + 字段脱敏，符合"个人信息保护"。

**问 3**：国密算法对照（约 160 字）

| 国密 | 类型 | 等价国际算法 | 性能差异（同强度对比） |
|---|---|---|---|
| **SM2** | 非对称（基于 ECC） | RSA-2048 / ECDSA-P256 | SM2 比 RSA-2048 **签名快 5-10 倍**，密钥短（256 bit vs 2048 bit）；与 ECDSA-P256 性能相当 |
| **SM3** | 哈希（256 bit 输出） | SHA-256 | 性能相当（差异 < 5%），抗碰撞强度等价 |
| **SM4** | 对称分组（128 bit 块/密钥） | AES-128 | 性能相当（差异 < 10%），SM4 在国产 CPU（鲲鹏 / 飞腾）上有指令集优化更快 |

**用途**：SM2 用于数字签名 + 密钥协商（替代 RSA）；SM3 用于完整性校验 + 国密 HMAC（替代 SHA-256）；SM4 用于数据加密 + TDE（替代 AES）。**金融行业受人民银行《金融行业 IT 标准》要求强制使用国密**。

**问 4**：加密 + 脱敏双层（约 110 字）

- **加密**解决**存储介质泄露**问题——磁盘被盗 / 备份外泄 / DBA 直接 dump，密文无密钥不可解；
- **脱敏**解决**正常业务下信息暴露**问题——业务人员、客服、报表查看时只需要看到 `1101**********0123` 而非完整身份证；

**为何不能只选其一**：① 仅加密：业务查询时还是要解密成明文，运维和报表系统仍能看到原值，等保三级要求"个人信息最小可见"不达标；② 仅脱敏：脱敏只在视图/接口层处理，**底层存储仍是明文**，磁盘失窃直接全量泄露。

**双层正解**：底层 AES-256 加密 + KMS 密钥；应用层按角色脱敏视图（管理员看部分明文、客服看脱敏、外部接口完全脱敏）。

**常见扣分点**：
- ❌ STRIDE 答成"输入校验 / 防 SQL 注入"——这是技术手段，不是威胁分类
- ❌ 等保三级把"5 项"答成"管理 5 项"——题问技术要求
- ❌ 国密算法对照混淆——SM2≠SM4，SM2 是非对称，SM4 是对称
- ❌ 把 SM3 答成对称加密——SM3 是 Hash
- ❌ "加密就够了不用脱敏"——等保三级和金融监管都要求字段脱敏

**高分技巧**：
- 引用人民银行《金融行业网络安全等级保护测评指南》JR/T 0072 体现专业度
- STRIDE 防御措施给出**深度防御组合拳**（认证 + 签名 + 审计 三层）比单一措施得分高
- 提到 **HSM、SOC、UEBA、SIEM** 等行业术语
- 国密引用《商用密码管理条例》合规依据

### 模拟题 2 · 政务系统零信任与国密 PKI 体系（25 分）

**【题干】**（约 780 字）

某省级政务"互联网+政务服务"平台升级，整合 23 个委办厅的 800+ 政务事项办理系统，对外服务 6000 万省内居民和 80 万企业法人。架构师 Z 牵头设计安全架构，需满足：① **国家政务云安全要求**；② **网络安全等级保护四级**（涉及公民隐私）；③ **国密合规**（密码法第 27 条强制）；④ **零信任**（"永不信任、持续验证"）。团队 24 人，周期 12 个月。

平台规模：日活 **400 万人次**、并发会话 **20 万**、峰值办件 **5 万件/小时**、关键接口 P99 **< 500ms**、数据敏感度涵盖**身份证 / 户籍 / 社保 / 医保 / 不动产 / 婚姻**。

Z 提交的安全架构核心决策：

1. **零信任架构 ZTA**：摒弃传统"内网即可信"模型，采用 **Google BeyondCorp** 思路 + Forrester ZTX 模型，对所有访问请求**默认不信任**；
2. **三大支柱**：
   - **SDP（软件定义边界）**：终端访问通过 SPA 单包认证 + 加密隧道，应用对未授权终端"隐身"；
   - **IAM（身份与访问管理）**：统一身份目录（CIDP）+ 基于风险的动态认证（RBA）+ FIDO2 无密码登录；
   - **MSG（微隔离）**：基于工作负载身份的东西向流量管控，零信任网关嵌入每个应用；
3. **国密 PKI 体系**：
   - 自建 CA 中心（基于国家政务云 CA 交叉认证），签发 SM2 证书；
   - 终端、服务、容器、数据库连接均颁发独立 SM2 证书；
   - 证书生命周期：注册 → 签发 → 分发 → 续签 → 吊销 → 销毁，CRL 每 4 小时同步，OCSP 实时验证；
4. **国密算法套件**：
   - 传输：**国密 SSL（GMSSL，SM2/SM3/SM4 套件）**；
   - 存储：SM4-CBC + KMS（HSM 国密版）；
   - 签名：SM2 + 国家时间戳（CTSA）；
   - 完整性：SM3 + HMAC-SM3；
5. **持续验证**：每次访问决策综合 **8 因子**——身份、设备、位置、时间、行为、网络、敏感度、风险评分；

**【参考答案】**

**问 1**：零信任 ZTA 与三大支柱（约 480 字）

**核心理念**："**永不信任、持续验证**"（Never Trust, Always Verify）。摒弃传统"内网即可信"假设——任何用户、设备、应用、网络都不预设信任，每次访问基于**身份 + 上下文 + 风险**动态评估并最小授权。

| 维度 | 传统边界安全 | 零信任 ZTA |
|---|---|---|
| **信任模型** | 内网默认可信 | 默认零信任 |
| **防护重心** | 边界防火墙 | 身份 + 数据 |
| **访问控制** | 一次登录长期可用 | 每次请求重新评估 |
| **网络结构** | 大平面网络 | 微隔离细粒度 |
| **失效面** | 边界一破全网沦陷 | 单点失陷不扩散 |
| **典型短板** | VPN 进内网即横扫 | （需高成熟度） |

**三大支柱协同**：

| 支柱 | 全称 | 作用 | 本架构落地 |
|---|---|---|---|
| **SDP** | Software Defined Perimeter | "**应用隐身**"——未授权请求看不到应用入口，攻击面收敛 | SPA 单包认证（敲门包）+ 动态 IP 白名单 + 加密隧道；外部攻击者扫端口看到的是"空气" |
| **IAM** | Identity and Access Management | "**身份即新边界**"——所有访问决策基于身份 | 统一 CIDP 身份目录 + FIDO2 无密码登录 + RBA 风险动态升级（异常登录强制人脸） |
| **MSG** | Micro-Segmentation | "**微隔离**"——东西向流量也要授权 | 每个应用嵌入零信任网关 + 工作负载身份（SPIFFE）+ 基于身份的策略（不基于 IP） |

**协同关系**：用户请求 → SDP 单包认证打开隧道 → IAM 验证身份 + 8 因子风险评分 → MSG 微隔离判断该身份能访问哪些工作负载 → 放行 + 持续监控。**任一环节异常，立即重新评估和拒绝**，形成闭环。

**问 2**：国密 PKI 工作流程（约 460 字）

**完整生命周期**：

```
注册（RA）→ 签发（CA）→ 分发 → 使用 → 续签/吊销 → 销毁
```

| 阶段 | 详细流程 |
|---|---|
| **注册** | 申请方（终端 / 服务 / 容器）通过 RA 提交身份信息 + 国密 SM2 公钥（私钥本地 HSM 生成永不外泄）→ RA 审核身份 → 提交 CSR 给 CA |
| **签发** | CA 验证 RA 签名 → 用 CA 私钥（HSM 内）对申请方信息 + 公钥进行 **SM2 签名** → 生成 X.509 v3 国密证书（OID 1.2.156.10197.1）→ 写入 LDAP 目录 |
| **分发** | 通过安全通道下发至申请方 + KMS 备份；CRL 同步至各 OCSP 节点 |
| **使用** | mTLS 双向认证：客户端发 ClientHello + 证书，服务端验签 + 查 OCSP，验证通过建立 GMSSL 通道 |
| **续签** | 证书到期前 30 天 RA 提醒，自动滚动更新；旧证书 CRL 标记过期 |
| **吊销** | 安全事件触发 → CA 立即吊销 → CRL 4 小时同步 + OCSP 实时下发；HSM 内私钥销毁（写零 + 多次覆写） |

**SM2 数字签名验证流程**：
```
签名（发送方）：
  H = SM3(M)                    // 报文哈希
  (r, s) = SM2_Sign(H, sk_A)    // 私钥 sk_A 生成签名 (r, s)
  发送 (M, (r, s), Cert_A)

验证（接收方）：
  从 Cert_A 中提取 pk_A
  pk_A 用 CA 公钥 SM2_Verify 验签（保证证书可信）
  H' = SM3(M)
  result = SM2_Verify(H', (r, s), pk_A)  // 真则不可抵赖
```

**SM4 数据加密流程**：
```
加密：
  生成会话密钥 K_session（HSM 内 RNG 产生 128 bit）
  C = SM4_CBC_Encrypt(M, K_session, IV)
  K_wrapped = SM2_Encrypt(K_session, pk_B)  // 用接收方公钥包裹会话密钥
  发送 (C, K_wrapped, IV)

解密：
  K_session = SM2_Decrypt(K_wrapped, sk_B)
  M = SM4_CBC_Decrypt(C, K_session, IV)
```
（SM2 慢但仅加密 16B 密钥，SM4 快用于大数据，混合密码学经典模式）

**问 3**：等保四级加严要求（约 200 字）

**等保四级 vs 三级关键加严**：

| 维度 | 等保三级 | 等保四级（加严） |
|---|---|---|
| 身份鉴别 | 双因素 | **三因素**（口令 + 证书 + 生物） |
| 集中管控 | 安全管理中心 | **强制三权分立 + 独立审计员** |
| 加密算法 | 推荐国密 | **强制国密**（不接受 RSA/AES） |
| 数据备份 | 异地备份 | **异地实时多副本** + RPO=0 |
| 漏洞扫描 | 月度 | **周度 + 持续监控** |
| 安全运营 | 7×8 | **7×24 SOC** |
| 审计保留 | 6 个月 | **1 年以上** |

**本架构落地**：
- 公民隐私字段（户籍、不动产）触发**绝密级**保护——SM4 加密 + 双人审批 + 全程录像 + 区块链存证；
- IAM 三因素（FIDO2 + 国密证书 + 人脸）覆盖管理员登录；
- 7×24 省级 SOC + UEBA 行为分析；
- 数据备份采用同城双活 + 异地三副本，RPO=0、RTO < 5 分钟；
- 国密 PKI 全覆盖，无非国密算法残留。
