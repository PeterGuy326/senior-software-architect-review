### 1. 关于 OSI 七层模型与 TCP/IP 四层模型的对应关系，下列描述**正确**的是：

A. TCP/IP 的网络接口层对应 OSI 的物理层

B. TCP/IP 的网际层对应 OSI 的传输层

✅ **C. TCP/IP 的网络接口层对应 OSI 的物理层和数据链路层**

D. TCP/IP 的应用层只对应 OSI 的应用层

**答案**：C
**解析**：OSI 七层（物理→数据链路→网络→传输→会话→表示→应用）；TCP/IP 四层（网络接口→网际→传输→应用）。映射关系：网络接口=物理+数据链路；网际=网络；传输=传输；应用=会话+表示+应用。速记口诀「**物链网传会表应**」（从下往上）。

### 2. 下列协议中，属于**网络层（网际层）**的是：

A. HTTP、FTP、SMTP

B. TCP、UDP

✅ **C. IP、ICMP、ARP、IGMP**

D. PPP、Ethernet

**答案**：C
**解析**：网络层协议核心是 IP，配套有 ICMP（差错报告，ping/traceroute 基础）、IGMP（组播管理）、ARP（IP→MAC，严格说在网络层与链路层之间，软考归网络层）、RARP（MAC→IP）。传输层是 TCP/UDP；应用层是 HTTP/FTP/SMTP/DNS 等；链路层是 PPP/Ethernet/HDLC。

### 3. 下列协议**端口号**对应**错误**的是：

A. HTTP — 80 / HTTPS — 443

B. FTP 控制连接 — 21 / 数据连接 — 20

C. SSH — 22 / Telnet — 23 / SMTP — 25

✅ **D. DNS — 35 / POP3 — 109 / IMAP — 144**

**答案**：D
**解析**：DNS 是 **53**（TCP+UDP 都用）、POP3 是 **110**、IMAP 是 **143**。常考端口速查：FTP 20/21、SSH 22、Telnet 23、SMTP 25、DNS 53、DHCP 67(Server)/68(Client)、HTTP 80、POP3 110、NTP 123、IMAP 143、HTTPS 443、SNMP 161（Agent）/162（Trap）。

### 4. 关于 TCP 与 UDP 的对比，下列描述**错误**的是：

A. TCP 面向连接、可靠传输；UDP 无连接、不可靠

B. TCP 有流量控制和拥塞控制；UDP 没有

C. UDP 报文头部 8 字节、开销小；TCP 报文头部 20 字节起

✅ **D. UDP 支持一对一、一对多、多对多通信；TCP 也支持一对多广播**

**答案**：D
**解析**：TCP **只支持一对一**（点到点）的全双工连接，**不支持广播和组播**；UDP 支持一对一、一对多、多对一、多对多，因此 DNS 查询、视频直播、组播、广播都用 UDP。常考"用 UDP 的典型应用"：DNS 短查询、TFTP、SNMP、视频/语音通话、组播。

### 5. TCP 三次握手中，**第二次握手**报文（SYN+ACK）由服务端发出时，下列描述**正确**的是：

A. 服务端进入 ESTABLISHED 状态

✅ **B. 服务端进入 SYN_RCVD 状态，等待客户端的最后一次 ACK**

C. 此时连接已建立，可以传输数据

D. 客户端进入 LISTEN 状态

**答案**：B
**解析**：三次握手状态变迁——客户端：CLOSED→SYN_SENT（发第 1 个 SYN）→**ESTABLISHED**（收到第 2 个 SYN+ACK 后发第 3 个 ACK）；服务端：LISTEN→**SYN_RCVD**（收到第 1 个 SYN、发第 2 个 SYN+ACK）→ESTABLISHED（收到第 3 个 ACK）。只有双方都 ESTABLISHED 才能传数据。**三次握手的根本目的是同步双方初始序列号 ISN**，而不是"建立连接"这么简单。

### 6. TCP 连接断开时进入 **TIME_WAIT** 状态需要等待 **2MSL**（约 60s）的根本原因是：

A. 防止服务器资源被快速释放

B. 等待对方关闭连接

✅ **C. 确保最后一个 ACK 能到达对端，并让旧连接的迟到报文在网络中消失**

D. 给操作系统留出处理时间

**答案**：C
**解析**：TIME_WAIT 是**主动关闭方**特有的状态。两大作用：①最后一个 ACK 若丢失，对方会重传 FIN，本方还能在 TIME_WAIT 期间响应，避免对方一直 LAST_ACK；②等 2MSL 让本次连接所有"迷路"的报文在网络中彻底消失，防止与下一次同四元组的新连接混淆。生产中 TIME_WAIT 过多可启用 `tcp_tw_reuse`（不可直接 `tcp_tw_recycle`，NAT 下有坑）。

### 7. 关于 IPv4 地址分类，下列描述**错误**的是：

A. A 类首位为 0，范围 1.0.0.0 ~ 126.255.255.255，主机号 24 位

B. B 类首两位为 10，范围 128.0.0.0 ~ 191.255.255.255

C. C 类首三位为 110，范围 192.0.0.0 ~ 223.255.255.255

✅ **D. D 类首四位为 1111，用于组播**

**答案**：D
**解析**：D 类首四位为 **1110**（范围 224.0.0.0 ~ 239.255.255.255），用于**组播**；E 类首四位为 **1111**（240.0.0.0 ~ 255.255.255.255），保留实验用。常考私有地址段：A 类 **10.0.0.0/8**、B 类 **172.16.0.0/12**、C 类 **192.168.0.0/16**、回环 127.0.0.0/8、APIPA 169.254.0.0/16。

### 8. 某公司分配到 C 类网络 192.168.10.0，要划分成 4 个子网，每个子网至少容纳 50 台主机，应采用的子网掩码是：

A. 255.255.255.0（/24）

✅ **B. 255.255.255.192（/26）**

C. 255.255.255.224（/27）

D. 255.255.255.128（/25）

**答案**：B
**解析**：4 个子网需借 2 位主机位（2²=4），C 类原主机位 8 位，借 2 位后剩 6 位主机位，每子网 2⁶−2=62 台主机 ≥ 50，满足。子网掩码 24+2=26 位 → 255.255.255.**11000000** = 255.255.255.**192**。若用 /25 只能分 2 个子网；用 /27 借 3 位剩 5 位主机位，2⁵−2=30 < 50，不够。**速记**：借 n 位 → 2ⁿ 个子网，剩余 m 位主机位 → 每子网 2ᵐ−2 台主机（减 2 是去掉网络地址和广播地址）。

### 9. 关于 **ARP 协议**，下列描述**正确**的是：

A. ARP 用于将 MAC 地址解析为 IP 地址

✅ **B. ARP 用于将 IP 地址解析为 MAC 地址，通过广播请求、单播应答**

C. ARP 工作在传输层

D. ARP 请求是单播、应答是广播

**答案**：B
**解析**：ARP（Address Resolution Protocol）将**IP→MAC**（同一局域网内）；反向 RARP 是 MAC→IP（已基本被 DHCP 取代）。ARP 工作流程：A 不知 B 的 MAC，**广播** ARP 请求（"谁是 IP=X"）；B 收到后**单播**应答自己的 MAC；A 缓存 ARP 表。ARP 工作在**数据链路层与网络层之间**（软考归网络层）。安全风险：**ARP 欺骗/中间人攻击**。

### 10. 关于 **DNS 解析**，下列描述**错误**的是：

A. 浏览器解析 www.example.com 时，先查本地 hosts 文件，再查本地 DNS 缓存，再问本地 DNS 服务器

B. 本地 DNS 服务器对客户端采用**递归查询**，对其他 DNS 服务器采用**迭代查询**

C. 域名层级从右到左：根（.）→ 顶级域（.com）→ 二级域（example）→ 主机（www）

✅ **D. DNS 只使用 TCP 53 端口，因 DNS 报文较大**

**答案**：D
**解析**：DNS **常规查询用 UDP 53**（报文 < 512 字节、快），**区域传送（主从同步）和大响应用 TCP 53**。两种查询方式：**递归**（客户端把任务全交给本地 DNS，得到最终答案）和**迭代**（本地 DNS 依次问根→顶级→权威，每步只给"下一跳"的地址）。**DNS 解析顺序**：浏览器缓存→OS hosts→OS DNS 缓存→本地 DNS（LDNS）→根→顶级→权威。

### 11. **HTTP 状态码** 与含义匹配**错误**的是：

A. 200 OK — 请求成功

B. 301 Moved Permanently — 永久重定向；302 Found — 临时重定向

✅ **C. 403 Forbidden — 资源不存在；404 Not Found — 没有权限**

D. 500 Internal Server Error — 服务端错误；502 Bad Gateway — 网关错误；504 Gateway Timeout — 网关超时

**答案**：C
**解析**：**403 Forbidden = 没有权限**（认证通过但无权访问）；**404 Not Found = 资源不存在**。两者互换是经典坑。状态码分类速记：**1xx** 信息、**2xx** 成功、**3xx** 重定向、**4xx** 客户端错误（401 未认证、403 无权、404 不存在、429 限流）、**5xx** 服务端错误（500 内部错误、502 网关错误、503 服务不可用、504 网关超时）。

### 12. 关于 **HTTPS / TLS** 工作机制，下列描述**错误**的是：

A. HTTPS = HTTP + TLS/SSL，默认端口 443

B. TLS 握手阶段通过非对称加密（RSA / ECDHE）交换对称密钥

C. 数据传输阶段使用对称加密（AES / ChaCha20），性能高

✅ **D. CA 证书的作用是加密通信数据**

**答案**：D
**解析**：**CA 证书的作用是验证服务器身份**（防中间人），而**不是**加密数据。服务器把"公钥+域名+CA 签名"放在证书里，客户端用 CA 公钥验证签名真伪。HTTPS 是**非对称加密+对称加密+数字证书**的组合：非对称解决密钥分发、对称解决性能、CA 解决身份验证。三大目标：**机密性**（加密）、**完整性**（HMAC）、**身份认证**（证书）。

### 13. 下列关于**路由协议**的描述，**正确**的是：

A. RIP 是链路状态协议、收敛快、适用于大型网络

✅ **B. OSPF 是链路状态协议，使用 Dijkstra 算法计算最短路径，适用于大中型自治系统内部**

C. BGP 是内部网关协议（IGP），用于自治系统内部

D. RIP 跳数最多支持 255 跳

**答案**：B
**解析**：路由协议两大分类——**IGP（自治系统内）**：RIP（**距离矢量**、最大 15 跳、易环路、收敛慢）、OSPF（**链路状态**、Dijkstra、收敛快、大中型网络主选）、IS-IS。**EGP（自治系统间）**：**BGP**（路径矢量、互联网核心路由协议）。距离矢量 vs 链路状态：前者只知"邻居说的距离"易环路；后者**每个路由器都有完整拓扑图**，独立算最短路径，收敛快。

### 14. **NAT（网络地址转换）** 的主要作用，下列描述**错误**的是：

A. 解决 IPv4 地址枯竭问题

B. 隐藏内网拓扑，提高安全性

C. 让多个内网主机共享一个公网 IP 上网

✅ **D. 提供端到端透明的通信，方便 P2P 应用穿透**

**答案**：D
**解析**：NAT 的副作用恰恰是**破坏端到端透明性**——内网主机没有公网 IP，外网无法主动发起连接到内网，P2P/VoIP 必须做 NAT 穿透（STUN/TURN/ICE）。NAT 三种类型：**静态 NAT**（一对一映射）、**动态 NAT**（地址池轮询）、**PAT / NAPT**（端口复用，一个公网 IP 带多个内网，**最常用**）。IPv6 因地址充足理论上不需要 NAT。

### 15. 某网络管理员要从远程加密登录服务器、并以加密方式传输文件，应分别选用的协议是：

A. Telnet / FTP

B. SSH / FTP

✅ **C. SSH / SFTP（或 SCP）**

D. Telnet / TFTP

**答案**：C
**解析**：**Telnet（23）和 FTP（20/21）都是明文传输**——用户名密码以明文发送，已被淘汰。安全替代：**SSH（22）** 取代 Telnet、**SFTP / SCP**（基于 SSH 通道、22 端口）取代 FTP、**HTTPS** 取代 HTTP。TFTP（69，UDP）是简单文件传输、无认证、明文，仅用于嵌入式/网络设备固件升级等可信内网场景。

### TCP 状态机（三次握手 / 四次挥手）

```
建连：CLIENT             SERVER
        ─── SYN ───────────►   (SYN_RCVD)
        ◄── SYN+ACK ───────
        ─── ACK ───────────►
       (ESTABLISHED)      (ESTABLISHED)

断连：CLIENT(主动)        SERVER
        ─── FIN ───────────►   (CLOSE_WAIT)
        ◄── ACK ───────────
       (FIN_WAIT_2)
        ◄── FIN ───────────    (LAST_ACK)
        ─── ACK ───────────►
       (TIME_WAIT, 2MSL)   (CLOSED)
       (CLOSED)
```

### 子网划分速记

- 借 **n** 位 → **2ⁿ** 个子网
- 主机位剩 **m** 位 → 每子网 **2ᵐ − 2** 台可用主机（减网络号+广播号）
- C 类常用切分：/25 = 2×126、/26 = 4×62、/27 = 8×30、/28 = 16×14
