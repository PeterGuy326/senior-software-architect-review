# 03 · 信息安全技术基础知识(教材第 4 章 / 大纲 §3)— 高频必考

> 综合选择 3–7 题，占 4–9%；论文/案例题中"系统安全性设计"方向直接命中。密码算法对比、数字签名流程、五个保护等级、SSL/PGP/IPSec 定位是**每年必考**。

## §3.1 信息安全基础

### CIA 三要素（+ 常扩展为五性）

| 属性 | 含义 | 反面威胁 |
|---|---|---|
| **保密性 Confidentiality** | 信息不被未授权者获知 | 窃听、泄露 |
| **完整性 Integrity** | 信息不被非法篡改 | 篡改、伪造 |
| **可用性 Availability** | 授权用户按需可用 | DoS/DDoS |
| **可控性 Controllability** | 信息流向和内容可控 | 失控外传 |
| **不可否认性 Non-Repudiation** | 事后可追溯、无法抵赖 | 抵赖 |

### 信息安全四大范围（必背）

**设备安全 + 数据安全 + 内容安全 + 行为安全**（层层递进，从物理到语义）。

- 设备安全：稳定性、可靠性、可用性（防偷、防毁、防电磁泄露）。
- 数据安全：静态数据的 CIA。
- 内容安全：语义层合规（防敏感/违法内容）。
- 行为安全：动态过程的机密性、完整性、可控性。

### 信息存储与网络安全

- 存储安全：物理安全、数据备份（完全/增量/差异）、灾难恢复（RPO 数据丢失量、RTO 恢复时间）。
- 网络安全：网络协议、访问控制、防火墙、IDS/IPS、VPN、审计。

## §3.3 信息安全系统组成框架（三大体系）

**技术体系 + 组织机构体系 + 管理体系**（技术是基础，组织是保证，管理是关键）。

## §3.4 加解密技术（核心必背对比）

### 对称加密

| 算法 | 密钥长度 | 分组 | 特点 | 备注 |
|---|---|---|---|---|
| **DES** | 56 bit | 64 bit | 快，已被破解，**不安全** | Feistel 结构 |
| **3DES** | 112/168 bit | 64 bit | 兼容 DES，安全性提升，慢 | DES 加密 3 次 |
| **IDEA** | 128 bit | 64 bit | PGP 早期使用 | 欧洲设计 |
| **AES** | 128/192/256 bit | 128 bit | **当前主流**，快且安全 | Rijndael 算法 |
| **RC4** | 可变 | 流密码 | 曾用于 SSL/WEP，已淘汰 | |
| **SM1/SM4** | 128 bit | 128 bit | **国密**，商密标准 | 中国自主 |

对称加密特点：**加解密同密钥、速度快、密钥分发难、不能签名**。

### 非对称加密

| 算法 | 数学基础 | 用途 | 备注 |
|---|---|---|---|
| **RSA** | 大整数因数分解 | 加密 + 签名 | 主流 |
| **ECC** | 椭圆曲线离散对数 | 加密 + 签名 | 密钥短、安全性高 |
| **DSA** | 离散对数 | **仅签名** | NIST 标准 |
| **DH** | 离散对数 | **仅密钥交换** | 不加密不签名 |
| **ElGamal** | 离散对数 | 加密 + 签名 | |
| **SM2** | 椭圆曲线 | **国密**，加密 + 签名 + 密钥交换 | 中国自主 |

非对称特点：**公钥加密私钥解 / 私钥签名公钥验、速度慢、密钥分发容易、可签名**。

### Hash 摘要算法（用于完整性与签名）

| 算法 | 输出长度 | 备注 |
|---|---|---|
| MD5 | 128 bit | 已碰撞，不推荐 |
| SHA-1 | 160 bit | 已碰撞，逐步弃用 |
| SHA-2（SHA-256/384/512） | 256+ bit | 主流 |
| SHA-3 | 可变 | 新标准（Keccak） |
| **SM3** | 256 bit | **国密**，中国自主 |

## §3.5 密钥管理与 PKI

- 对称密钥分配：Needham-Schroeder、Kerberos（对称票据）。
- 公钥加密体制 = 一对（公钥公开 + 私钥保密）。
- **CA（证书颁发机构）**：签发 X.509 证书，绑定公钥与身份；PKI = CA + RA + 证书库 + CRL + 应用接口。
- 数字证书内容：**版本 / 序列号 / 签名算法 / 颁发者 / 有效期 / 主体 / 主体公钥 / CA 签名**。

## §3.6 访问控制与数字签名

### 访问控制模型

| 模型 | 全称 | 特点 |
|---|---|---|
| **DAC** | 自主访问控制 | 客体属主定权限，灵活但弱 |
| **MAC** | 强制访问控制 | 系统按标签强制（BLP/Biba） |
| **RBAC** | 基于角色 | 主流，按岗位授权 |
| **ABAC** | 基于属性 | 细粒度、动态 |

访问控制实现三种数据结构：**访问控制矩阵 / 访问控制表 ACL（按客体）/ 能力表 Capability（按主体）**。

### 数字签名流程（必背）

**发送方**：明文 M → Hash 得摘要 H → **发送方私钥**加密 H = 签名 S；把 (M, S) 发送。
**接收方**：用**发送方公钥**解密 S 得 H'，再对 M Hash 得 H；比较 H == H' → 验签通过。

作用：**完整性 + 不可否认性 + 身份认证**（但**不提供保密性**——保密性需再用对方公钥加密 M）。

## §3.7 抗攻击技术

### 常见攻击与防御

| 攻击 | 原理 | 防御 |
|---|---|---|
| **DoS** | 单点大流量耗尽资源 | 限速、防火墙、黑名单 |
| **DDoS** | 分布式 DoS（SYN Flood/UDP Flood/CC） | 流量清洗、CDN、云 WAF、SYN Cookie |
| **ARP 欺骗** | 伪造 MAC-IP 映射 | 静态 ARP 绑定、DAI 动态 ARP 检测、划分 VLAN |
| **DNS 欺骗** | 篡改 DNS 应答 | DNSSEC、指定权威 DNS、检查响应完整性 |
| **IP 欺骗** | 伪造源 IP | 入口过滤（RFC 2827）、双向鉴别 |
| **端口扫描** | 全 TCP / SYN / FIN / ACK / 代理扫描 | 关闭无用端口、IDS 检测异常 SYN |
| **重放攻击** | 截获报文重放 | 时间戳、随机数 Nonce、序号 |
| **SQL 注入 / XSS / CSRF** | Web 层输入未过滤 | 参数化查询、WAF、CSP、Token |

### 系统加固

- **TCP/IP 堆栈强化**：禁止 IP 源路由、防 SYN Flood（SYN Cookie/半连接队列）、关闭 ICMP 重定向。
- **系统漏洞扫描**：Nessus、OpenVAS；及时打补丁。

## §3.8 保障体系与评估（重点）

### 五个安全保护等级（GB 17859-1999，必背）

| 级别 | 名称 | 特点 |
|---|---|---|
| **第 1 级** | 用户自主保护级 | DAC 自主访问控制 |
| **第 2 级** | 系统审计保护级 | 加入审计与身份鉴别 |
| **第 3 级** | 安全标记保护级 | 引入 MAC 强制访问 + 安全标记 |
| **第 4 级** | 结构化保护级 | 形式化安全模型、TCB 结构化 |
| **第 5 级** | 访问验证保护级 | 引入访问监控器，最高级 |

配套：**等保 2.0（GB/T 22239-2019）**，网络安全等级保护制度，覆盖云、移动、物联网、工控。

### 三大安全协议定位（必背对比）

| 协议 | 层次 | 用途 | 特点 |
|---|---|---|---|
| **SSL / TLS** | 传输层与应用层之间 | Web 保密传输（HTTPS） | 端到端；C/S 型；不改 IP |
| **PGP** | 应用层 | 邮件加密 + 签名 | 基于信任网 WoT，非 CA |
| **IPSec** | 网络层 | VPN、IP 层机密与完整 | 支持 AH（完整性）/ ESP（机密+完整）；两种模式：传输 / 隧道 |
| **S/MIME** | 应用层 | 邮件加密（企业） | 基于 X.509 CA |
| **SET** | 应用层 | 电子支付 | 已淘汰 |
| **HTTPS** | = HTTP over SSL/TLS | Web | 443 端口 |

### 风险评估五要素（必背）

**资产 Asset + 威胁 Threat + 脆弱性 Vulnerability + 安全措施 Safeguard + 风险 Risk**。

风险计算：**风险值 R = f(资产价值 A, 威胁 T, 脆弱性 V)**；措施降低脆弱性/威胁 → 降低风险。

### 安全管理规章

- 国际：**ISO/IEC 27001**（ISMS 信息安全管理体系）、ISO/IEC 27002（控制措施）、**CC（ISO/IEC 15408）**（通用评估准则，EAL1–EAL7）。
- 美国：**TCSEC 橘皮书**（D/C1/C2/B1/B2/B3/A1 七级）、NIST SP 800 系列。
- 国内：**GB 17859**（五级）、**GB/T 22239 等保 2.0**、密码法。

## 必背要点速记

1. 对称记 **DES(56)/3DES/IDEA(128)/AES(128-256)/SM4**；非对称记 **RSA(因数分解)/ECC/DSA仅签/DH仅换/SM2**。
2. 数字签名 = **发送方私钥签 Hash，接收方公钥验**；只保完整+不可否认，**不保密**。
3. 保护等级五级：**自主 → 审计 → 标记 → 结构化 → 访问验证**。
4. 三协议定位：**SSL 在传输层上做 Web，PGP 应用层做邮件（WoT），IPSec 网络层做 VPN**。
5. 风险评估五要素：**资产、威胁、脆弱性、安全措施、风险**。
6. 信息安全四范围：**设备 → 数据 → 内容 → 行为**。
7. 抗 DDoS 用 SYN Cookie + 流量清洗 + CDN；抗 ARP 用静态绑定 + DAI + VLAN。

## 常考题型示例

- 【综合选择】关于 SSL、IPSec、PGP 的说法正确的是（ ）。—— 答：SSL 位于**传输层与应用层之间**，为 Web 提供端到端加密；IPSec 位于**网络层**，为 VPN 提供机密与完整；PGP 位于**应用层**，为邮件提供加密与签名，采用**信任网**而非 CA。
- 【综合选择】某公司希望邮件既保密又能防抵赖，正确做法是（ ）。—— 答：发送方先用**自己私钥**对邮件 Hash 签名（防抵赖 + 完整性），再用**接收方公钥**加密邮件正文（保密性），接收方反向解密验证。
- 【案例】列出某系统的风险评估五要素并说明彼此关系。—— 答：**资产 A、威胁 T、脆弱性 V、安全措施 S、风险 R**；威胁利用脆弱性作用于资产产生风险，安全措施用于降低脆弱性/威胁从而降低风险。
